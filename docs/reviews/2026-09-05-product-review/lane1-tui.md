# Lane 1 — Pancetta TUI: visual design, hierarchy, flow, interaction, polish

Reviewed 2026-09-05 against `main` (v0.9.6). Method: read `pancetta-tui/src/{ui/*.rs,widgets/mod.rs,keymap.rs,view.rs,config.rs}` fully, `app.rs`/`tui_runner.rs` via targeted reads + two helper sweeps; ran the release binary under `--replay assets/demo-wav` in an isolated `$HOME` (mock rig, no audio hardware) via vhs at **80x24, 100x30, 132x40, 200x55**, 24 captures per size (startup, idle, all 4 views, every overlay/modal, 3 zooms, post-burst). Screenshot names below refer to `<scratch>/lane1/shots/s<COLS>x<ROWS>_<NN>_<name>.png`.

## 1. Executive summary

- **Aesthetics 5/10 · Hierarchy 5/10 · Flow 6/10 · Polish 4/10.** The bones are right: dense single screen, keyboard-first, 15 s glance→decide→keypress rhythm, and the TX-placement instrument is a genuinely original idea no other FT8 client has.
- The redesign spec's structure (4 views, focus model, station card, instrument) shipped, but half of its §5 "quick wins" did not: **cyan still means ≥6 things**, the chrome has **no overflow strategy** (UTC clock is the first casualty at ≤100 cols), and **no panel except Band Activity adapts its columns**.
- Two safety-adjacent keyboard bugs: **Ctrl+C starts a CQ** (unguarded `Char('c')`), and the **quit-confirm modal swallows Shift+Q emergency stop**.
- The `?` help overlay **truncates without scrolling on every terminal under 46 rows** — the cut-off entries are `d x q Shift+Q Esc`.
- Feedback is a single overwritten string with no TTL that **every decode clobbers** ("Decoded: …"), sitting at the far right of the status line where ≤100-col terminals truncate it.
- Below 132x40 the layouts degrade badly: QSO Status renders incoherent fragments, DX Hunter/Callers headers collapse to single letters, Hunt view shows 0–1 rows. 80x24 (SSH on a phone) is effectively unusable.
- The waterfall has z-order collisions ("TX 1▼0▼"), grayscale-only palette, no gain control; the placement instrument ships placeholder columns ("Live"/"Quiet" always "-") and an unlabeled axis.
- Text quality is inconsistent: Debug-format leaks (`View: Hunt`, `Rig: NotConnected`, `Reply step: Rr73`), raw `very_rare`, three different TX-offset ranges on screen at once, mixed casing/units.
- Health panel's TX-output indicator is semantically inverted vs its own doc comment; idle QSO Status shows red "-50 dB" gauges on a healthy station — false alarms erode trust.
- What must not regress: the single-scorer instrument, callsign-pinned focus + two-tier highlight, keymap single-source-of-truth with drift test, non-modal E-stop banner, two-press `x`, UTC-everywhere, the min-size guard.

## 2. Ranked hit list

Format: `[Pn] [effort] title — problem (evidence) — change — why it matters`. Effort S <½ day, M 1–3 days, L >3 days.

### P0

1. **[P0][S] Ctrl+C starts a CQ.** `KeyCode::Char('c')` has no modifier guard (`tui_runner.rs:1504-1508`); raw mode delivers Ctrl+C as `Char('c')+CONTROL`. Only `k` is modifier-guarded (`:1645`). — Guard every letter arm with `key.modifiers.is_empty()` (one helper), map Ctrl+C to the quit-confirm. — A reflex chord keys the transmitter.
2. **[P0][S] Quit-confirm swallows the emergency stop.** `quit_confirm_visible` arm matches y/Enter/n/Esc/q and `_ => {}` swallows everything else, including `Q` (`tui_runner.rs:956-970`); the out-of-band modal does the same (`:943-953`). — Shift+Q must bypass every modal check; put it first in `handle_key_event`. — An E-stop that can be dead for one dialog is not an E-stop.
3. **[P0][S] Help overlay truncates silently.** 39 bindings + 5 chrome rows = 44 rows, `min(area.height-2)`, no scroll state (`tui_runner.rs:2160-2221`). At 40 rows the last visible entry is `m`; `d x q Shift+Q Esc` are cut (s132x40_11_help, s100x30_11_help). At 80x24 the `Wrap` makes it wrap+truncate into garbage (s80x24_11_help). — Scroll it (↑↓/PgUp), or two-column layout above 120 cols, or group by `Category` with Session & safety pinned first. — The one place a new operator learns Shift+Q is the one place it isn't shown on a laptop terminal.
4. **[P0][M] Title bar has no overflow strategy; the UTC clock dies first.** `render_title_bar` appends spans, pads with `saturating_sub`, never truncates or prioritizes (`ui/mod.rs:611-884`). At 100 cols the clock reads "21:12:" (s100x30_10_operate); at 80 it is gone and `DECODE:` is cut mid-word (s80x24_10_operate). — Priority-ordered chips with a drop order (entity → decode-ms → FREQ → view chip …; never drop clock/TX policy/callsign); right-anchor the clock first, then fill left. — FT8 is a clock-disciplined mode; the clock and TX policy must never leave the screen.

### P1

5. **[P1][M] Status message is one overwritten String with no TTL, clobbered by every decode.** `app.status_message` is set at ~25 sites; `add_decoded_message` ends with `status_message = format!("Decoded: {}", …)` (`app.rs:1817`); no timestamp/TTL anywhere. A 28-decode burst overwrites "Calling W1AW…" or "⚠ 1500 Hz busy in both windows — not parking" 28 times in one frame. It also sits last in the status line, so it truncates first at ≤100 cols ("Decod", s80x24_10). — Introduce `Toast {text, level, since, ttl}` ring (≤3 visible, 5–8 s TTL, errors sticky until keypress) in a dedicated left-anchored slot; move "Decoded:" to a counter. — Feedback you cannot see is the same as no feedback.
6. **[P1][S] Station Health TX-output indicator is inverted / false alarm.** `dot(app.tx_output_default)` with text "system default" (green) vs "NOT default — check device" (red) (`ui/mod.rs:1751-1760`), but `tx_output_default == true` is documented as *the misconfig* ("PTT keys, audio on speakers", `app.rs:1113-1117`) and drives a ⚠ badge elsewhere. Startup default `false` therefore shows a red "check device" on a healthy station (s132x40_13_health). Same panel prints `Rig: {:?}` → "NotConnected". — Flip the semantics, reuse the badge wording, add `Display` for `RigConnDisplay`. — A health panel that lies once is never trusted again.
7. **[P1][M] Band Activity ignores need status.** `DecodedMessageView` carries `needed/atno/band_needed/worked_before` but `create_message_row` colours the callsign green unless `worked_before` (`band_activity.rs` call_style); no ATNO/needed marker or colour. DX Hunter shows `+▲◇VA3WL` in red for the same station while Band Activity shows `VA3WL` in green (s132x40_10_operate). — Reuse `need_marker()` and the DX-Hunter call style; add a `Need` glyph column (`!`/`+`/`▲`) when width ≥ 100. — Band Activity is where the eye lives; "is this one worth calling" must be there, as in JTDX/GridTracker.
8. **[P1][M] QSO Status needs ≥15 rows and degrades into fragments.** Fixed `Length(3,3,2,2,Min1,1,0,1)` chain (`qso_status.rs:render_qso_status`); Operate gives it 40 % of the lower column. At 100x30 it shows "Status", "Seq", "TX: Never", gauge *titles without bars*, "Monitoring…" (s100x30_10_operate); Hunt/Run `Min(5)` gives 3 unrelated lines (s132x40_21_hunt, s80x24_21_hunt). — Height-tiered renderer: ≤4 rows = one-line summary (call · state · Now/Next · countdown); 5–9 = summary + ladder; ≥13 = full. — The ladder + Now/Next is the primary in-QSO instrument; fragments are worse than a compact line.
9. **[P1][M] DX Hunter and Callers don't adapt columns; full-width `Min` flex swallows the row.** No `visible_columns()` equivalent; at 100x30 headers are "Gr SNR Ra Rp Las Pr" and calls truncate to "+▲VA" (s100x30_10_operate); at 80x24 "G S R R L P" (s80x24_10). In Hunt/Run the `Min(8)` Entity / `Min(10)` Msg column flexes to ~80 cols, pushing SNR/Pri to the far edge (s132x40_21_hunt, s132x40_22_run, s200x55_21). — Port `visible_columns(width)` to both panels; cap Entity ~24 / Msg ~22 and spend spare width on a real column (DF, bearing, need, full message). — 80 columns of eye travel between callsign and SNR kills the glance rhythm.
10. **[P1][M] Hunt view collapses under 30 rows.** `Length(7)+Percentage(45)+Percentage(25)+Min(5)` (`ui/mod.rs:compute_hunt_rects`): at 80x24 Band Activity gets header only ("3/10", 0 rows) and DX Hunter 1 row (s80x24_21_hunt); at 100x30 4/3/3 rows (s100x30_21_hunt). — Per-view minimum content height, or fold Band Activity away below N rows. — The flagship view must not be the worst one on a laptop.
11. **[P1][S] Waterfall z-order collisions.** `Waterfall::render` draws the TX label, then the `signal_freqs` ▼ loop overwrites it ("TX 1▼0▼", "TX▼▼5▼0 ⚠"), and the TX cursor line cuts the axis label ("15│0") (`widgets/mod.rs`, marker loop after label; s132x40_23_monitor, s80x24_23_monitor, s200x55_23_monitor). — Draw order: heat → occupancy → axis → ▼ markers → TX cursor → TX label last with cleared bg. — The one label on the instrument is unreadable.
12. **[P1][M] Chip/colour de-dup (spec §5 quick win) not done.** Accent cyan = panel titles, table headers, `FREQ: HOLD`, `DECODE:`, `SPLIT TX`, `TX off:`, `QSOs:`, every overlay border, Callers Freq cell, DX Entity cell, `[HOUND]` badge bg (`ui/mod.rs:672-700,728,757`; `qso_status.rs` hound; `tui_runner.rs:2189,2070`). Yellow = focus/selected AND warning AND CQ AND E-only. — Semantic tokens in `Theme` (`alarm`, `caution`, `tx`, `need`, `focus`, `info`, `muted`); info chips neutral (fg only, no bold); colour reserved for state. — A colour that means six things means nothing.
13. **[P1][S] Idle QSO Status shows red "-50 dB" gauges.** `snr_tx.unwrap_or(-50)` → red `Gauge` labelled "-50 dB" on every idle screen (`qso_status.rs:render_snr_meters`; all `*_10_operate`). — Render "—" / hide when `None`. — False-alarm colour on a healthy station.
14. **[P1][S] Station card entity lookup has no fallback.** `render_line1` uses only `dx_stations.get(call).entity_name` (`station_card.rs`); DX Hunter falls back to `dxcc::entity_for_callsign`. Result: card "LC1TVY — --- needed" while DX Hunter says "Norway" one panel over (s132x40_01_idle_empty; "--- new" in every operate shot). — Share `resolve_entity()` from `qso_status.rs`. — The card's whole job is "who is this".
15. **[P1][S] TX-offset bounds disagree in three places on screen at once.** Arrows/`[`/`]` clamp 200–2900 (`tui_runner.rs:1388,1404`), `o` modal enforces 300–2700 (`app.rs:626,631`; body `ui/mod.rs:1322`), the `o` status hint says "200–2900" (`tui_runner.rs:1806`) — both visible simultaneously (s132x40_25_offsetmodal). UX-audit batch 3 had set 200–2500 (modulator range). — One `TX_OFFSET_RANGE` const, one string. — Operators read numbers.
16. **[P1][M] Overlays hardcode colours; Light theme is half-applied.** Help/quit/device picker/all overlay borders use `Color::Cyan/Black/White` literals, never `app.theme` (`tui_runner.rs:2185-2305`, `ui/mod.rs:1299,1329,1358,1597,1686`). — Route through `Theme`; add `HighContrast`/colour-blind variants. — Theme support that stops at the panels is a broken promise.
17. **[P1][S] Row-highlight styles are inconsistent and ugly.** Band Activity: solid accent bg + black fg erases SNR/CQ colours (all `*_10_operate`). DX Hunter/Callers: `REVERSED|BOLD` inverts each cell's own fg → rainbow patches on the selected row (s132x40_17_dxzoom). — One selection style: subtle bg keeping cell fg + `▶` gutter. — Selection should frame the data, not repaint it.
18. **[P1][S] Callers hint row overwrites the panel's bottom border.** `hint_area.y = area.y + area.height - 1` (`callers.rs`), so "(no callers)" / "reply ◂ grid ▸ Enter=send" replaces the border and leaves a visible gap in every screenshot. — Render inside `block.inner()` as the last row, or as `title_bottom`. — Broken box-drawing reads as a crash.
19. **[P1][S] Dist column truncates its own unit.** `format_distance` returns "1.8k km" (7 chars) into `Length(6)` → "1.8k k" everywhere (`band_activity.rs`, `ui/mod.rs:format_distance`; s132x40_10). — Integer km right-aligned, width 5, header "km". — Wrong-looking numbers in a numeric table.
20. **[P1][M] No attention mechanism for directed-at-me / failures.** No bell, no `SLOW_BLINK`, no transient flash anywhere (grep: zero hits); errors share the status string. Directed rows are yellow+bold with `→` (good) but nothing pulls the eye when one lands. — Optional bell on directed-at-me and QSO complete/fail; 1-slot bg flash; sticky red toast for errors. — WSJT-X operators rely on the red "to me" line + sound; a 3-hour session is mostly not looking at the screen.

## 3. "World-class" bets

1. **Slot clock + parity as the top-level instrument.** Replace "Pancetta TUI" with `E ▮▮▮▮▮▯▯ 08s │ TX:O` — current slot parity, our TX parity, elapsed, decode-phase tick, boundary flash. Every FT8 operator's eye already goes there in WSJT-X; here it goes to nothing. Pair with a per-slot separator row in Band Activity so the timestamp column can shrink or vanish.
2. **A real design-token layer.** `Theme` grows semantic roles (`alarm`, `caution`, `tx`, `need`, `focus`, `engaged`, `info`, `muted`, `selection_bg`) consumed by *every* renderer incl. overlays; info chips lose colour, alarms keep it; one selection style; glyph-backed states; `Dark`, `Light`, `HighContrast`, `Deuteranopia`. Ship a `TestBackend` golden per theme per view so it can't drift again.
3. **Context footer + command palette.** lazygit/k9s idiom: the footer shows the ≤6 actions valid *right now* for the focused panel/view/modal; `:` opens a fuzzy palette over `KEYBINDINGS` (already a table — 80 % built). This also dissolves the case-pair keymap problem: rare actions (Hound, Fox, tune, mode) live in the palette, freeing letters.
4. **Responsive layout engine with a compact tier.** `view_layout(view, size)` picks a tier (`Compact <100x30`, `Standard`, `Wide ≥160`) and every panel exposes `render(area, tier)`: adaptive columns everywhere (generalize Band Activity's `visible_columns`), QSO Status compact line, DX Hunter/Callers minimum rows, and a dedicated 80x24 "phone/SSH" layout (Band Activity + one-line QSO + instrument strip). Golden-snapshot each tier.
5. **Band Activity as the decision surface.** Need-aware colouring (ATNO/new-DXCC/new-grid/worked) from fields already on the row; quick filters (all / CQ / needed / to-me) as a chip in the panel title; 1-slot flash + optional bell on directed-at-me; worked rows dimmed; `Enter` on a row = call; header-click sort. This is what GridTracker/JTDX users miss most, and it is mostly wiring.

## 4. Already excellent — do not regress

- **Single-scorer TX-placement instrument**: display and autonomous allocator share one path; the vacancy-first strip + BEST list is a new FT8 instrument. Keep the invariant and the `Enter=park` flow through existing hold machinery.
