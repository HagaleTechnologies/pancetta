# Lane 5 — Engineering quality as the operator feels it

Repo `/Users/thagale/Code/pancetta` @ `c90cb34` (main, v0.9.6 + 3 commits). Apple M4 Pro (12 cores), macOS. All runs used an isolated `HOME=<scratch>/lane5/home`, `--replay assets/demo-wav`, `[rig.interface]` disabled, no hardware touched. file:line refs are exact at this commit. Method: direct measurement (`/usr/bin/time -l`, `ps -M`, `sample`, pty harness with staged terminal resizes), full `cargo test`/`clippy`/`deny`, and five focused read-only code audits (panic/failure, durability, time, security, config/release).

## 1. Executive summary

Pancetta's resilience *architecture* is ahead of most ham software: supervisor with restart budgets, fail-closed TX gates, PTT RAII + watchdog, retained diagnostics overlay, atomic 0600 config writes, a real SNTP check in `doctor`, 3361 green tests in 7 minutes, clean `cargo deny`, SHA-pinned actions. The *last mile* is where an operator gets hurt. Several things the docs promise don't exist: config hot-reload is never constructed (the RUNBOOK's "edit TOML to suspend autonomous TX" does nothing), `--log-format json` and `--metrics` are no-ops. The autonomous slot tick is monotonic and drifts off UTC after sleep/NTP-step, so a laptop lid-close mid-session produces late partial transmissions every cycle. A DX-cluster disconnect turns a tokio worker into a 100 % spin for the session. A dead audio device does not stop autonomous PTT. The QSO commit path never fsyncs, the startup index rebuild unlinks `qso.db` under an open pool, and uploads are fire-and-forget with no outbox (PAN-57). A TUI startup/render failure leaves the terminal in raw mode with exit code 0 and — because `shutdown.rs` matches `Ok(Ok(_))` — the real error is swallowed; the QRZ password leaks into debug logs via `reqwest::Error`'s URL. Windows, the deploy target, is compiled only on tag and never tested. Kernel time exceeds user time during decode (27.9 s sys vs 14.6 s user over 103 s) on a 31-thread process — fine on an M4, a real risk on a Pi. Scores (1–10): **reliability 6 · performance 7 · durability 5 · observability 6 · security 7 · maintenance health 7**.

## 3. Ranked hit list

`[Pn] [S/M/L] title — operator-visible symptom — root cause (file:line) — proposed change`. `(PAN-x)` = tracked in Linear.

### P0

- **H-1 [P0][M] Autonomous slot tick never re-anchors to UTC** — after lid-close/wake or an NTP step (Pi 4 has no RTC; first sync after boot *steps*) every autonomous decision fires at a fixed phase φ into the slot; for φ ≲ 7 s that's a late-start partial TX every cycle (undecodable past ~3 s: pure QRM from a keyed rig), for φ > 7.2 s every reply is deferred a full cycle — `pancetta/src/coordinator/autonomous.rs:1065-1073` `interval_at(Instant::now()+initial_delay, 15 s)` + `MissedTickBehavior::Delay`, never reset; DSP re-derives from `Utc::now()` every window (`dsp.rs:701-705`) so decode and decision silently diverge — replace with per-iteration `sleep_until(next_slot_start(Utc::now()))` on the active `slot_ns`; warn when a tick's wall time is >200 ms off a boundary.
- **H-2 [P0][S] Config hot-reload is documented but never constructed** — `docs/CONFIG.md:511-527` ("Config reloaded: 12 keys updated"), `docs/RUNBOOK.md:296-299` (suspend autonomous TX by editing `[autonomous].enabled=false`, "picked up within seconds"), `ARCHITECTURE.md:18`, `main.rs:58` all promise it; `ConfigHotReload` (`pancetta-config/src/hot_reload.rs:37-282`) has zero constructors in the binary; `coordinator/health.rs:107-109` admits "the wired hot-reload task is a no-op"; `MessageType::ConfigUpdate` has no producer. On an unattended transmitter the RUNBOOK's TX-suspend procedure silently does nothing — wire it behind the existing `classify_config_reload` guard, or delete the docs and say "restart the service". Fix the module first: debounce *skips* rather than coalesces (`hot_reload.rs:127-135`), so an editor's truncate-then-write applies the empty file (`Config::default()` validates) and drops the real write.
- **H-3 [P0][M] Dead audio output does not inhibit TX** — unplug the USB codec and autonomous mode keeps keying PTT every slot into silence; `coordinator/audio.rs:373-380` `queue_output` failure is logged + one ephemeral status line; nothing in `tx.rs`/`qso.rs`/`autonomous.rs` reads `health_audio_alive`; `TransmitComplete{success:true}` still fires — gate `SetPtt{true}` (`tx.rs:3899`) on an `audio_output_ok` flag, emit `TransmitComplete{success:false}` + a retained Error diagnostic.

### P1

- **H-4 [P1][S] DX-cluster disconnect → 100 % CPU spin for the session** — telnet clusters drop idle clients; reader exits on EOF (`pancetta-dx/src/cluster.rs:261-265`), dropping `spot_tx`; `receive_spot()` then returns `None` instantly (`:471-477`); the coordinator arm `Ok(None) => yield_now()` (`pancetta/src/coordinator/dx_cluster.rs:117-119`) spins a tokio worker forever; `auto_reconnect`/`reconnect_delay_seconds` (`cluster.rs:32-34`) are never read — on `None`, break and reconnect with capped backoff.
- **H-5 [P1][S] TUI startup/render failure leaves the terminal in raw mode + alt screen, exit 0, cause invisible** — reproduced: a terminal that doesn't answer the cursor-position query (`ESC[6n`) that ratatui 0.30's `Terminal::clear()` issues (`ratatui-core-0.1.2/src/terminal/buffers.rs:148`) makes `TuiRunner::new` fail after `enable_raw_mode` + `EnterAlternateScreen` (`pancetta-tui/src/tui_runner.rs:503-513`); observed output was exactly `ESC[?1049h ESC[6n`, never `ESC[?1049l`, and the process ended "Application completed successfully". `cleanup()` (`:2333-2340`) runs only on the happy path; every `?` in `run()` (`:583,586,587,595,604,639`) bypasses it; no `Drop` impl exists in `pancetta-tui`; the panic hook (`main.rs:1718`) only logs — add a `TerminalGuard` RAII, restore the terminal inside the panic hook *before* printing, and exit non-zero when the TUI wrapper returns `Err`. (Answering the DSR in the harness produced a fully working TUI that survived all resizes — the code under the terminal is solid.)
- **H-6 [P1][S] Shutdown swallows component errors** — `pancetta/src/coordinator/shutdown.rs:138-140` matches `Ok(Ok(_))` on `Result<Result<Result<()>, JoinError>, Elapsed>`; the `_` is the task's own `Result`, so a task that returned `Err` logs "completed successfully" at DEBUG (verified: the H-5 failure logged "Task 4 (TUI) completed successfully"; zero log lines carried the crossterm error text) — match `Ok(Ok(Err(e)))`, log WARN with the error.
- **H-7 [P1][M] `tx_late_max_ms` default 8000 permits provably undecodable TX; key-time cursor is uncapped** — `pancetta-config/src/station.rs:60-66` rationale ("two of three Costas arrays still in window") is wrong: cursor = mstr − 500 ms, so at 8 s only the third Costas array and 25/58 data symbols remain (75 coded bits < 91 info bits); the deferral decision is frozen on `request_received_at` (`tx.rs:2942`) but the cursor is recomputed from fresh `Utc::now()` at key time (`:3714-3721`) bounded only by waveform length — default ≤3000 ms; re-check the fresh cursor at `:3714` and defer/skip.
- **H-8 [P1][M] No fsync on the QSO commit path; power loss loses the just-logged QSO from both stores** — `pancetta-qso/src/adif_log_writer.rs:141` `flush()` only (module doc `:9-12` rejects `sync_data` as "10 000× more expensive" — at ≤1 QSO/15 s it's free); SQLite `synchronous=NORMAL` in WAL (`async_database.rs:334-339`) durable only at checkpoint; a truncated trailing record also merges into the next on rebuild (`adif.rs:900-912`) — `sync_data()` per record; header-if-empty rather than header-if-new (`adif_log_writer.rs:69,100`).
- **H-9 [P1][M] Startup ADIF→index rebuild unlinks `qso.db` under the already-open pool** — `coordinator/qso.rs:2082` opens the pool, `:2215` `replay_from_adif` does `remove_file(db_path)` (`async_database.rs:941`) leaving `-wal/-shm` shared by two inodes; trigger is mtime-based (`qso.rs:2185-2210`) and fires after any crash/SIGKILL (WAL main-file mtime only moves at checkpoint) — rebuild into `qso.db.new` + rename before constructing the logger; compare `<EOR>` count to row count instead of mtimes.

## 4. Five "world-class" moves

1. **Make UTC the only slot authority.** One `SlotClock` service (UTC-derived `next_boundary()`, monotonic-vs-wall skew detector, sleep/wake + NTP-step events on the bus) consumed by autonomous, DSP, TX and the queued-call TTL; on skew > 1 slot: flush the DSP buffer, drop in-flight QSOs with a `ClockStep` reason, resync. Retires H-1, H-7, H-16, H-21, H-32, H-39 as a class and gives the TUI a live clock-offset chip from median DT (H-22).
2. **A durable QSO ledger.** fsync'd ADIF append → per-service upload outbox in SQLite (status, attempts, next_retry) drained with backoff and surviving restart; index rebuilt atomically via `qso.db.new`+rename from `<EOR>` counts; ADIF backed up on rotation; one diagnostics row per outcome ("W1AW logged ✓ · LoTW queued · ClubLog failed 401"). Closes H-8…H-11, H-17, H-30, PAN-57.
3. **Fail-closed TX needs a live audio path and a persistent fault surface.** `audio_output_ok` + `health_audio_alive` gate in the TX worker, `TransmitComplete{success:false}` on any output error; the same latch pattern replaces the overwrite-prone status line for supervisor, PTT-stuck and upload-failure states (H-3, H-19, H-20).
4. **Ship what the docs promise — or delete the promise.** Wire the (fixed) `ConfigHotReload` or remove the docs; wire `--log-format json` and real loopback-bound Prometheus metrics (decode latency, budget exhausted, TX attempts/defers/drops, QSOs by outcome, outbox depth); add `pancetta support-bundle` (redacted config, doctor, last N log lines, tier cache, thread dump); refresh SECURITY.md to the code (H-2, H-12, H-13, H-23, H-34, H-51, H-52).
5. **Prove the deploy target.** Weekly Windows-gnu check+test lane; a Pi-4 (or QEMU aarch64) soak that runs the replay corpus and asserts CPU/RSS/decode-latency budgets; symbol artifacts, provenance attestation and an SBOM on every release; MSRV pin; a Windows service installer (H-14, H-15, H-35–H-38).
