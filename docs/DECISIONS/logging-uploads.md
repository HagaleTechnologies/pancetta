# Logging and uploads

## QSO logging — ADIF + SQLite hybrid

`~/.pancetta/qsos.adi` is the durable, append-only ADIF source of truth (vendor-neutral; point WSJT-X / N1MM / LoTW / eQSL at this file directly). `~/.pancetta/qso.db` is a sqlx-backed queryable index rebuilt from the ADIF on startup if missing or stale — safe to delete. `AdifLogWriter` (pancetta-qso) writes ADIF records; `AsyncQsoLogger` (pancetta) persists to both stores. Existing operators auto-migrate: first startup after upgrade exports the legacy DB into a fresh ADIF before flipping over. **TX_PWR** (2026-07-05): `AdifProcessor::qso_to_adif` previously hardcoded `tx_pwr: None` ("not tracked in QSO metadata") — every rendered ADIF record, local or uploaded, always omitted transmit power. `AdifProcessor` now carries a `station_power_watts: Option<f64>` set via `set_station_power_watts`/`with_station_power_watts` (0 = unconfigured, omits `TX_PWR` rather than emitting a literal `TX_PWR:0`); the coordinator stamps it from `config.station.power_watts` at both real construction sites — the ADIF source-of-truth writer (`AdifLogWriter::set_station_power_watts`, coordinator/qso.rs) and the per-QSO upload subscriber (`start_qso_upload_subscriber`, same file — this is what ClubLog/QRZ/eQSL/LoTW/cqdx actually upload) — so it's consistent everywhere, not just at the upload boundary. `async_logger`/`async_database`'s internal SQLite-index rendering and the `pancetta export` CLI command were **not** threaded (no config access at those call sites without a larger signature change; not user-impacting since neither is the operator-facing upload/log-file path) — flagged as a follow-up if ever needed. **Attribution comment** (2026-07-05): `AdifProcessor::qso_to_adif` appends a fixed software-attribution string ("Using cqdx.io & Pancetta -- https://cqdx.io https://github.com/HagaleTechnologies/pancetta") to every QSO's `COMMENT` field, after any operator notes and the Hound "HOUND" marker. Graceful degradation via `append_attribution`/`COMMENT_SOFT_MAX_LEN` (255 chars): full form with URLs when it fits, a short form ("Using cqdx.io & Pancetta") when notes are long, and omitted entirely rather than ever truncating the operator's own notes.

**ADIF import** (PAN-127, 2026-10): `pancetta import <FILE> [--dry-run]` (`pancetta/src/main.rs::import_command`) appends the new contacts to `qsos.adi` verbatim as one block, in one write and one fsync, through `adif_log_writer::prepare_import_block` + `write_import_block` (PAN-214, 2026-10), rendered by `AdifProcessor::render_record` (CALL, QSO_DATE, TIME_ON first, then the rest by name; never through `qso_to_adif`, which would reset QSL status to `N` and stamp the attribution comment onto another logger's contacts), then indexes the new contacts. An existing `qso.db` only gets the new rows, through `QsoDatabase::insert_adif_records` (the record→row conversion `replay_from_adif` uses), because a running station may hold it open and a rebuild deletes the file; a missing one is built with `replay_from_adif`. From before the first write until every new row is indexed, a `qso.db.rebuild` file beside the index (`QsoDatabase::rebuild_marker`) marks it as missing rows; startup rebuilds a marked index and removes the marker only once the rebuild succeeds (a failed one is retried at the next start), because an import stopped between appending and indexing can leave a `qso.db` missing rows yet newer than `qsos.adi`. The new rows commit in one SQLite transaction, so an index never holds part of an import. An import leaves a marker it did not create in place, and keeps its own when `qso.db` was already older than `qsos.adi` (adding the new rows does not repair the old gap, and a later live write could make `qso.db` look current). The marker names who asked for the rebuild (`import <receipt>` or `undo <receipt>`); an import or undo that finds one already there writes its own name into it, and an import removes its own marker only under the logbook lock and only while it still holds that name, so an undo run while an import is indexing keeps its rebuild request even though the import's index commit can leave `qso.db` newer than the undo's rewrite. Planning is pure (`pancetta-qso/src/adif_import.rs::plan_import`): a record is a duplicate when callsign (case-insensitive, suffix-sensitive), band (BAND, else derived from FREQ; empty or pancetta's `NNMHZ` fallback matches any band) and mode (SUBMODE if present, else MODE) match and the start times are at most `DUPLICATE_WINDOW_MINUTES` = 30 apart. Thirty minutes is the tolerance LoTW uses to match one QSO across two logs, and it also absorbs pancetta's CQ-start `TIME_ON` and other loggers' `HHMM` times; repeats within the file are counted separately from contacts already in the logbook. **Logbook lock (PAN-214, 2026-10).** Every write to `qsos.adi` holds an exclusive `std::fs::File` lock (`flock` on Unix, `LockFileEx` on Windows; the OS drops it when the holder exits or crashes) on the empty sibling file `qsos.adi.lock` (`pancetta-qso/src/logbook_lock.rs::LogbookLock`). The lock is on a sibling file because Windows locks are mandatory: locking `qsos.adi` itself would make WSJT-X, TQSL and anything else the operator points at it fail to read it. The live `AdifLogWriter` takes it for each header or record write (milliseconds), polling every 50 ms for up to 60 s (`LIVE_LOCK_WAIT`, an `INFO` on the first busy try); at 60 s, or when the lock file cannot be opened, it logs a `WARN` and writes without the lock, because a completed QSO is never dropped. The import plans and prints its header without the lock (`--dry-run` never locks or creates anything), then polls for up to 30 s (`IMPORT_LOCK_WAIT`), printing `Waiting for Pancetta to finish writing to …` on the first busy try, and refuses with exit 1 and nothing changed once that passes; an I/O error opening the lock also refuses. It holds the lock from re-reading the logbook through backup, receipt and append, so its records form one contiguous block no live QSO lands inside, which keeps PAN-127's "Running Pancetta: Allowed" without a stop-the-station rule. Under the lock it re-reads `qsos.adi`: a logbook that only grew is replanned (`replan_after_logbook_growth`), one that changed any other way is refused. The unlocked `AdifLogWriter::append_record`/`sync_all` the import used before were removed, so no bulk-append path bypasses the lock. Before the first write, `create_backup` (the PAN-90 helper: exclusive create, `.bak` then `.bak.N`, 0600) copies `qsos.adi`, and the import stops unless the backup equals the re-read bytes exactly; an import that adds nothing makes no backup. **Receipt and undo (PAN-214, 2026-10).** Before the append, an import that adds contacts writes and fsyncs a receipt, `~/.pancetta/imports/import-YYYYMMDD-HHMMSS.json` (UTC; `-2`, `-3`… on collision; exclusive create, 0600; `adif_import::ImportReceipt`, `version` 1), holding the logbook path, the import file, the backup, the byte `offset` where the block starts and the exact appended text (`added`); a failed append deletes it only once the logbook is back to its pre-import length (a part-written block is trimmed first; a refusal because the logbook moved wrote nothing and trims nothing), and keeps it otherwise, so appended contacts always have a receipt. It keeps the exact bytes rather than a hash: no SHA crate is a dependency, an exact compare is the strongest check, and the receipt doubles as a readable record of what was added. `pancetta import --undo <RECEIPT>` (`undo_import_command`) takes the same lock and 30 s wait, finds `added` at `offset`, else as its only occurrence anywhere in the logbook (so imports can be undone in either order), backs the logbook up with `create_backup` (the copy must equal the bytes read), and removes exactly that block in place (`remove_import_block`: write the tail at the block's start, `set_len`, fsync), keeping everything logged before or after it. In place, never by rename: a running station keeps one `O_APPEND` handle on `qsos.adi` for its lifetime, and a replaced file would leave that handle writing its later QSOs into the unlinked old one; Rust std opens Windows files with read, write and delete sharing, so the in-place rewrite works there too, and undo needs no stopped station. It refuses, changing nothing, when the receipt cannot be read, is not a receipt or is of another version, is already undone (`undone_at` set), names another logbook, or the block is no longer there byte for byte (the error names the pre-import backup, or says there was no logbook before the import). That byte-exact check is also what makes the live writer's write-anyway fallback, and an older binary that takes no lock, safe: undo never deletes a record it did not add. Just before the rewrite (so a failure to mark changes nothing), the rebuild marker (`mark_index_incomplete`) is written when `qso.db` or a marker exists, rather than deleting rows in an index a running station holds, so `pancetta export` keeps listing the removed contacts until the next start rebuilds it (deleting rows by id is follow-on work); after the rewrite the receipt is rewritten atomically (`<receipt>.tmp`, `sync_all`, rename) with `undone_at` set, and kept. Imports are never uploaded: the CLI builds no `QsoManager`, so no `QsoCompleted` fires (the PAN-57 outbox takes live completions only; uploading imported history is follow-on work). A legacy install (`qso.db` without `qsos.adi`) is refused until a start has migrated it. Reader rules (`AdifProcessor::parse_bytes`): a tag tokenizer over the raw bytes (line breaks carry no meaning, a file without `<EOH>` is all records, many records per line), non-UTF-8 files decoded as Latin-1, `HHMM` times accepted, and one result per record, so a malformed record is reported by position without hiding the rest (`parse_string` keeps its whole-file error for replay). **Length unit (PAN-214, 2026-10).** ADIF counts characters but allows only ASCII in `.adi` files; for UTF-8 values writers differ (pancetta writes byte counts, HAMRS, Xlog and Cloudlog reportedly count code points), so each file's unit (`LengthUnit`, reported as `AdifParse::length_unit`) is decided once, replacing PAN-127's per-value tie-break that kept the byte cut whenever it fit. A UTF-8 file with any non-ASCII byte is tokenized twice, once preferring bytes and once characters; a value contradicts a pass when that unit's cut lands on no field boundary (just before a tag that ends a value: `<EOR>`, `<EOH>` or one carrying a length, so a lookalike such as `<x>` does not count) and the other unit's cut does, and the pass then takes the other cut so it stays in sync. The pass with fewer contradictions wins; a tie, including a file with no deciding value, reads as bytes, pancetta's own convention, so a pancetta-written file (where every byte cut lands on a boundary) can never be misread and the startup replay and round-trip guard are unaffected. A value both units read cleanly, such as tag-shaped text inside a character-counted value, decides nothing and follows the file's unit, so `<NOTES:9>€€€<X:1>z` in a character-counted file keeps `NOTES=€€€<X:1>z`. ASCII and Latin-1 files are parsed once. A declared length that runs past the end of the input, or whose cut lands on no field boundary after swallowing a real tag, is `AdifError::LengthMismatch` (`Field length does not match its value: COMMENT:999`): only that record is unreadable, and scanning resumes at the value's first byte, so the `<EOR>` the value would have swallowed closes the bad record and the next one reads on its own (before, `<COMMENT:999>` swallowed every later contact into one value, and `<COMMENT:30>` silently gave a record the next contact's `TIME_ON` and `MODE`). Text after a value that swallows no tag stays legal, as ADIF allows, and gives no evidence for either unit. A torn last record (a crash mid-write leaving a final value that runs past end of file) now reads as `LengthMismatch` where its value used to be clamped silently; the startup replay then fails as a whole and `prepare_local_qso_index` keeps the existing index, as for any unreadable logbook, and `pancetta import --dry-run` reports the logbook as unreadable. Round-trip guard: a record that does not read back to the same fields through `render_record` → `parse_string` → `record_to_qso` is reported unreadable instead of appended, because one unreadable record in `qsos.adi` aborts the startup index rebuild part-way. **Type indicators (PAN-214, 2026-10).** An imported field's ADIF data-type indicator is kept by field name in `AdifQso.field_types` and `QsoMetadata.adif_field_types` (`APP_LOGGER_SCORE` → `N`; serde default and skipped when empty, so pancetta's own QSOs, older rows and their stored JSON are unchanged, and an older binary just drops the indicator on export), and `qso_to_record` + `generate_string`/`generate_record` write it back, so `pancetta export` gives `<APP_LOGGER_SCORE:2:N>42` instead of `<APP_LOGGER_SCORE:2>42`. A separate map, not type-suffixed `tags` keys, because other code looks tags up by plain name (QSL_SENT/QSL_RCVD). Header fields and pancetta's own QSOs carry none. Startup ordering: the migrate/rebuild decision (`prepare_local_qso_index`, `coordinator/qso.rs`) now runs before `start_local_qso_log_writers` opens either file. Opening first created an empty `qsos.adi` that made a legacy-only `qso.db` look stale (the rebuild wiped it) and an empty `qso.db` that made a missing index look current (it was never rebuilt).

## Local TX log (PAN-122)

Every frame whose audio the TX worker hands to the audio output is appended to `~/.pancetta/tx-log.jsonl` as one JSON line (`pancetta/src/coordinator/tx_log.rs`; fields and semantics in `docs/CONFIG.md`, "TX log"). It exists because the only per-frame record before it, the TUI's `TxFrameLogged` event, travels the best-effort message bus: headless mode never drains the TUI channel, so once 10,000 TUI-bound messages pile up every event is dropped, and the app log (`tracing_appender::non_blocking`, lossy) has no structured TX record at all. It is distinct from the remote agent's `~/.pancetta/agent-audit.log` (security finding F-12); the two are not merged.

- **Direct call, not the bus (D1).** The TX worker calls `TxFrameLog::append` itself at Step 7. The bus drops silently on a full, missing or disconnected destination (PAN-38), which is exactly the loss being fixed.
- **Path (D2).** `<home>/.pancetta/tx-log.jsonl`, home = `pancetta_home_override` (tests), else `dirs::home_dir()`, else `.`; outside `logs/`, which tracing-appender prunes. Under `cfg(test)` with no override the fallback is `temp_dir()/pancetta-test-home-<pid>`, never a developer's real home.
- **Format (D3).** JSON Lines, schema `v: 1`: `{v, utc, mode, dial_hz, offset_hz, text, origin, qso_id}` (the field set the 2026-09-05 review proposed, plus `v`). `utc` is the same value the TUI event carries. `dial_hz` is the split-aware effective TX dial (`effective_tx_dial`, the resolver the band-plan gate uses), `null` when unknown (0).
- **Durability (D4).** Per batch: serialize into one buffer, `create_dir_all(parent)`, open with `create(true).append(true)`, one `write_all`, `sync_data`; on Unix a best-effort parent-directory `sync_all` after creating a file. No `BufWriter`, no held handle, so a crash right after the append cannot lose the record, and moving or deleting the file never strands a stale handle. `coordinator::tx_log::tests::record_survives_process_abort_immediately_after_append` re-runs the test binary as a child that appends and calls `std::process::abort()`.
- **One writer thread (D5).** A `std::thread` named `pancetta-tx-log` fed by an unbounded `std::sync::mpsc` of jobs, each with a `tokio::sync::oneshot` ack: FIFO, a single writer, and no blocking-pool threads piling up behind a stalled disk. Input is bounded by the physical TX rate (at most one batch per slot), so the queue cannot grow meaningfully. It works on current-thread runtimes, where `block_in_place` would panic.
- **Bounded wait (D6).** The worker waits at most `TX_LOG_ACK_WAIT` = 250 ms for the ack, then logs `TX log: write still pending after 250 ms; …` and carries on; the job stays queued and is written when the disk responds. Step 8's abort/disarm polling therefore starts at most 350 ms late (`TX_PLAYBACK_START_WAIT` 100 ms + `TX_LOG_ACK_WAIT` 250 ms; PAN-71), and PTT release is never blocked. Measured in a Linux container during planning: open + 147 B append + `fdatasync` + close, median 0.075 ms, p99 0.123 ms, max 3.15 ms; the Windows target is expected to be slower, which is why the wait is bounded rather than assumed fast.
- **Only on `Enqueued` (D7).** The record is written inside `Ok(SendIfOutcome::Enqueued)`, before the existing `log_tx_frame` call and with the same timestamp, the playback-start instant or its enqueue-time fallback (PAN-71); `Denied`, `Dropped` and refused-before-PTT frames get no record (PAN-134's "denied or dropped audio never appears as aired"), and no suspension was added before the audio enqueue. A bundle is one batch (one fsync), one line per item, one shared `utc`.
- **Fail-open (D8).** A write failure never stops TX: the writer thread logs one `ERROR` per failed batch, `TX log: could not record N frame(s) to <path>: <error>. Frames: [<utc> <mode> <offset> Hz "<text>", …]`, so the app log still holds a copy. Logging is not a Part 97 requirement, and a full disk should not take the station off the air.
- **Rotation (D9).** `TX_LOG_MAX_FILE_BYTES` = 8 MiB, `TX_LOG_ARCHIVES` = 7, `.1` newest: when `len > 0 && len + batch > max`, drop `.7`, shift `.6→.7 … .1→.2`, then active → `.1`. A batch is never split and an empty file is never rotated. A failed rotation keeps appending to the active file rather than losing the record. About 55,000 records per file (~150 B each).
- **Replay (D10).** `--replay` uses `TxFrameLog::disabled()`: no thread, no file (listed in `replay_mode()`'s consumers). `--test-tx` and rig-less dev runs are logged, because their audio does go out.
- **Lifetime (D11).** `ApplicationCoordinator::tx_frame_log` is created by `ensure_tx_frame_log` on the first `start_transmitter_component` and reused on every supervisor restart, so the file never has two writers (the `tx_requeue` shape). Two pancetta processes sharing one home could race rotation; that setup is unsupported.

Limits: `sync_data` cannot see through firmware or OS write-cache lies, so the promise is "survives a process crash; fsync requested for OS crash or power loss". If the disk stalls and the process is killed during the stall, that frame's record can be lost; the `WARN` line marks such windows. Out of scope here: headless mode still never drains the TUI channel (a separate follow-up).

### Playback-start timestamp (PAN-71)

`TxFrameRecord.utc` and Band Activity's `TxFrameLogged.timestamp` now use the
instant the audio thread observes the output callback consume a frame's first
sample. This applies to first-pass frames, operator-triggered mid-frame re-keys,
and every item in a summed multi-TX buffer. Tune still logs no frame. The schema
stays at `v: 1`; existing records keep their earlier enqueue-time meaning.

The output ring tracks cumulative samples written and retired. Before pushing a
non-empty buffer into a ring with space, the producer arms its first sample's
one-based position. The callback publishes whether a pop crossed that position,
then publishes the retired count. A clear advances the count without reporting
playback. The observer reads the retired count before the start flag. These are
atomic operations; the callback takes no lock, allocates nothing, and reads no
clock. A generation tag invalidates marks when the output ring is replaced.
Empty buffers and full rings get no mark, so a later buffer cannot confirm them.

`PlaybackStartAck` travels with `AudioOutput` through the relay's FIFO. Like
`DeliveryAck`, its clones share a first-settle-wins slot; dropping every copy
reports `Dropped` immediately. The audio thread holds one pending mark and polls
it before and after each TX-command check. A played mark settles `Started(now)`;
a discarded mark, a failed queue operation, or an empty write settles
`NotStarted`. Arming another mark re-polls the old one and settles it as
`NotStarted` if still waiting. The single-slot limit is deliberate: the worker
waits for each frame's ack before sending another.

The TX worker waits at most 100 ms after authorized enqueue. A confirmed start
supplies the shared timestamp; otherwise the worker keeps the enqueue instant.
A pending or not-played ack produces a `WARN` naming the frame. A dropped ack
produces `DEBUG`, because no-audio, stub and replay modes have no audio thread.
Records are appended before the TUI event in frame order, including records for
buffers known to have been discarded. Denied and dropped bus sends get neither.
The playback deadline still starts at enqueue, so acknowledgement and log waits
do not extend key-down. They add at most 350 ms before Step 8's abort polling.

Planning measured a device-free stand-in callback over 15 runs per case: a
normal queue call took 2.4 to 4.4 ms, while the first sample was popped after about
10 ms with a 10 ms callback period. Re-key playback took about 10.5 to 10.7 ms or
20.2 to 20.3 ms with 10 ms or 20 ms periods. A callback stalled for 60 ms discarded
the replacement buffer in all 15 runs when it serviced the overdue flush.
Those measurements motivated the 100 ms bound; they are not device or RF tests.

The timestamp is the audio thread's observation, not a driver timestamp or RF
onset. Device buffering and audio-thread scheduling remain outside that
measurement. Late flushes are reported truthfully but are not prevented here.
Callback clock reads would violate the real-time rule; callback heartbeats and
ring emptiness cannot identify a buffer. A separate ack channel would lose FIFO
correlation. A detached logger would lose worker ordering and shutdown guarantees.
A re-key-only change would give `utc` two meanings, so all logged frames use the
same bounded wait. Racing that wait with abort polling was rejected in favor of
the existing bounded-wait policy.

## Per-QSO online-logbook upload (opt-in)

on `QsoEvent::QsoCompleted`, the coordinator (`pancetta/src/coordinator/qso.rs::start_qso_upload_subscriber`) uploads that single QSO to **ClubLog** (`https://clublog.org/realtime.php`) and/or **QRZ Logbook** (`https://logbook.qrz.com/api`, `ACTION=INSERT`) as one ADIF record (rendered identically to the source-of-truth `qsos.adi` record via `AdifProcessor::qso_to_adif` → `generate_record`), and/or to **cqdx.io** — the operator's own first-party logbook — as the structured `QsoRecord` JSON its `POST /api/v1/qsos` endpoint expects (built from the same `QsoMetadata` via `cqdx_record_from_metadata`, using the dial+offset RF frequency stamped on completed metadata; see `docs/cqdx-api-requirements.md`). ClubLog/QRZ clients live in `pancetta-dx/src/qso_upload.rs`; the cqdx logbook method is `pancetta-cqdx::CqdxClient::log_qso` (defensively parses 201/2xx→`Logged`, 409 or in-band `{"status":"duplicate"}`→`Duplicate`, 401→`Unauthorized`), returning `QsoUploadOutcome`. All three default OFF and require config: `[network.clublog]` / `[network.qrz_logbook]` (validation rejects enabled-without-credentials), and `[network.cqdx]` (`enabled` + non-empty `token`; gate `cqdx_logbook_upload_enabled`). The cqdx logbook upload replaced the old `cqdx_bridge.report_qso` fire-and-forget call in the QsoCompleted handler (no double-upload). Uploads never block/fail the QSO pipeline; a duplicate is non-fatal everywhere. **Pending-upload queue (PAN-57, 2026-10).** ClubLog, QRZ Logbook, eQSL and cqdx.io uploads go through one durable outbox, `~/.pancetta/upload_outbox.json` (`pancetta-dx/src/upload_outbox.rs::OutboxStore`, schema_version 1, pretty JSON, mode 0600, rewritten atomically via `<file>.tmp` + `sync_all` + rename). Each upload is written there *before* its first attempt and removed only when the service accepts it or reports a duplicate; the queue is drained at every start. A file that cannot be read is renamed to `upload_outbox.json.corrupt-<unix-seconds>` (never deleted) and pancetta starts empty; if even the rename fails, the worker keeps state in memory and never overwrites the file that session. The stored payload is the rendered ADIF record (or the cqdx `QsoRecord` JSON, built once at completion so retries hit the same idempotency key); credentials are added by the clients at send time and are never stored. Failures are classified at the client boundary (`DxError::Upload { class, message }`, `UploadFailureClass`, `upload_failure_class_for_status`; the `Display` text is unchanged): **Transient** = 5xx, 408/425/429, timeouts, connection errors, unrecognised responses (`Parse`); **LoginRejected** = 401/403, QRZ `RESULT=AUTH`, an eQSL bad login, cqdx `Unauthorized`/invalid token; **RecordRejected** = any other 4xx, QRZ `RESULT=FAIL`, an oversized 2xx body. Delivery runs in one worker per process (`pancetta/src/coordinator/upload_outbox.rs`, started by the first `start_qso_component` with a destination and reused on Qso restarts, because a crash-restart can briefly leave the old subscriber alive and two writers on one file must never happen). Each destination is a lane with one attempt in flight: transient failures follow `[network.reliability.retry]` (default 3 tries: 0 s, ~1 s, ~2 s, jittered; the section is now validated) and then a 5-minute slow lane; sends are spaced 1 s apart; the lane picks never-tried entries first, then the least recently tried, so one failing entry cannot block the rest. A login rejection stops that destination for the session (config is snapshotted per run) and keeps every upload queued; a record rejection holds that one entry. Held entries are released at every start; nothing is dropped automatically (the operator discards by editing or deleting the file while pancetta is stopped). The queue is capped at 5,000 entries; new uploads past that are refused (the QSO is still in `qsos.adi`). State reaches the operator as PAN-89 readiness-strip **Warnings** (never Blockers, so uploads never hold TX): `⚠ <SERVICE> LOGIN REJECTED`, `⚠ <SERVICE> REJECTED N QSO(S)`, `⚠ <SERVICE> UPLOAD RETRYING · N QUEUED`, `⚠ UPLOAD QUEUE FULL`, each acknowledgeable and listed in Shift+S, plus one Shift+D `qso.upload` row per state change. Delivery is at-least-once and relies on each service's duplicate handling; a crash between a service accepting an upload and the queue write means one benign re-send at the next start. LoTW keeps its single tqsl attempt. Durable receipt states, delivery status in Recent QSOs, explicit restart reconciliation and uploading imported history are follow-on work, not PAN-57. Credentials/tokens stay local and are never logged (target `qso.upload`). **LoTW** and **eQSL** per-QSO upload landed 2026-06-18 (same `start_qso_upload_subscriber` wiring, both default OFF, validation rejects enabled-without-creds): **eQSL** POSTs the rendered ADIF (with `<EQSL_USER>`/`<EQSL_PSWD>` header fields) to `importADIF.cfm`; **LoTW** shells out to the operator's `tqsl` CLI to digitally sign + upload (`tqsl -a all -d -x -u -l "<station_location>" <adi>`; verified live against a real TQSL 2.8.6 install/certificate 2026-09-03, PAN-65 — `-x`/`--batch` is required or tqsl starts its interactive GUI and never exits, accumulating one orphaned window per QSO; the invocation is wrapped in a bounded timeout that kills a hung `tqsl`). Both clients (`EqslClient`, `LotwClient`/`LotwUploadClient`) are in `pancetta-dx/src/qso_upload.rs`; config `[network.lotw]` (`tqsl_path` + `station_location`) / `[network.eqsl]` (`username` + `password`).
