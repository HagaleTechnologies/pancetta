# Logging and uploads

## QSO logging — ADIF + SQLite hybrid

`~/.pancetta/qsos.adi` is the durable, append-only ADIF source of truth (vendor-neutral; point WSJT-X / N1MM / LoTW / eQSL at this file directly). `~/.pancetta/qso.db` is a sqlx-backed queryable index rebuilt from the ADIF on startup if missing or stale — safe to delete. `AdifLogWriter` (pancetta-qso) writes ADIF records; `AsyncQsoLogger` (pancetta) persists to both stores. Existing operators auto-migrate: first startup after upgrade exports the legacy DB into a fresh ADIF before flipping over. **TX_PWR** (2026-07-05): `AdifProcessor::qso_to_adif` previously hardcoded `tx_pwr: None` ("not tracked in QSO metadata") — every rendered ADIF record, local or uploaded, always omitted transmit power. `AdifProcessor` now carries a `station_power_watts: Option<f64>` set via `set_station_power_watts`/`with_station_power_watts` (0 = unconfigured, omits `TX_PWR` rather than emitting a literal `TX_PWR:0`); the coordinator stamps it from `config.station.power_watts` at both real construction sites — the ADIF source-of-truth writer (`AdifLogWriter::set_station_power_watts`, coordinator/qso.rs) and the per-QSO upload subscriber (`start_qso_upload_subscriber`, same file — this is what ClubLog/QRZ/eQSL/LoTW/cqdx actually upload) — so it's consistent everywhere, not just at the upload boundary. `async_logger`/`async_database`'s internal SQLite-index rendering and the `pancetta export` CLI command were **not** threaded (no config access at those call sites without a larger signature change; not user-impacting since neither is the operator-facing upload/log-file path) — flagged as a follow-up if ever needed. **Attribution comment** (2026-07-05): `AdifProcessor::qso_to_adif` appends a fixed software-attribution string ("Using cqdx.io & Pancetta -- https://cqdx.io https://github.com/HagaleTechnologies/pancetta") to every QSO's `COMMENT` field, after any operator notes and the Hound "HOUND" marker. Graceful degradation via `append_attribution`/`COMMENT_SOFT_MAX_LEN` (255 chars): full form with URLs when it fits, a short form ("Using cqdx.io & Pancetta") when notes are long, and omitted entirely rather than ever truncating the operator's own notes.

## Per-QSO online-logbook upload (opt-in)

on `QsoEvent::QsoCompleted`, the coordinator (`pancetta/src/coordinator/qso.rs::start_qso_upload_subscriber`) uploads that single QSO to **ClubLog** (`https://clublog.org/realtime.php`) and/or **QRZ Logbook** (`https://logbook.qrz.com/api`, `ACTION=INSERT`) as one ADIF record (rendered identically to the source-of-truth `qsos.adi` record via `AdifProcessor::qso_to_adif` → `generate_record`), and/or to **cqdx.io** — the operator's own first-party logbook — as the structured `QsoRecord` JSON its `POST /api/v1/qsos` endpoint expects (built from the same `QsoMetadata` via `cqdx_record_from_metadata`, using the dial+offset RF frequency stamped on completed metadata; see `docs/cqdx-api-requirements.md`). ClubLog/QRZ clients live in `pancetta-dx/src/qso_upload.rs`; the cqdx logbook method is `pancetta-cqdx::CqdxClient::log_qso` (defensively parses 201/2xx→`Logged`, 409 or in-band `{"status":"duplicate"}`→`Duplicate`, 401→`Unauthorized`), returning `QsoUploadOutcome`. All three default OFF and require config: `[network.clublog]` / `[network.qrz_logbook]` (validation rejects enabled-without-credentials), and `[network.cqdx]` (`enabled` + non-empty `token`; gate `cqdx_logbook_upload_enabled`). The cqdx logbook upload replaced the old `cqdx_bridge.report_qso` fire-and-forget call in the QsoCompleted handler (no double-upload). Uploads are best-effort, spawned per-upload, and never block/fail the QSO pipeline; a duplicate is non-fatal everywhere. Credentials/tokens stay local and are never logged (target `qso.upload`). **LoTW** and **eQSL** per-QSO upload landed 2026-06-18 (same `start_qso_upload_subscriber` wiring, both default OFF, validation rejects enabled-without-creds): **eQSL** POSTs the rendered ADIF (with `<EQSL_USER>`/`<EQSL_PSWD>` header fields) to `importADIF.cfm`; **LoTW** shells out to the operator's `tqsl` CLI to digitally sign + upload (`tqsl -d -a all -l "<station_location>" -u <adi>`; the exact invocation is marked `OPERATOR-CONFIRM(lotw)` — untestable without the operator's certificate). Both clients (`EqslClient`, `LotwClient`/`LotwUploadClient`) are in `pancetta-dx/src/qso_upload.rs`; config `[network.lotw]` (`tqsl_path` + `station_location`) / `[network.eqsl]` (`username` + `password`). (The older `pancetta-dx/src/lotw.rs` web-scrape client — QSL download — is a separate concern, left intact.) **QRZ paid XML lookup** (`pancetta-dx/src/qrz_xml.rs`, `QrzXmlClient`): read-side enrichment client (auth→cached session key→callsign lookup for name/grid/dxcc/country/state), `[network.qrz_xml]` (`username`+`password`), default OFF, validation rejects enabled-without-creds. **Wired (2026-06-18) as a gated, best-effort, session-cached grid-enrichment fallback at QSO-completion time** in `start_qso_upload_subscriber` (`coordinator/qso.rs`): on `QsoEvent::QsoCompleted`, when the their-grid is MISSING, `maybe_enrich_grid_from_qrz` looks up the contra-callsign and `merge_qrz_lookup` fills `grids.theirs` with a *valid* (`pancetta_core::GridSquare`-checked) QRZ grid before the ADIF record is rendered, so all downstream uploads carry it; the operator name is appended to `notes` (display/log only). It only fills MISSING fields (never overrides decoded/cqdx data), caches each callsign's hit **or** miss for the session (`Mutex<HashMap<call, Option<QrzLookup>>>`), runs entirely off the hot decode loop (once per completed QSO), and never blocks/fails the pipeline (errors logged at debug, target `dx.qrz`). Disabled → no client built, zero overhead. The subscriber now also spawns when QRZ XML alone is enabled (no upload target required). **cqdx needed-grids**: `CqdxClient::fetch_needed_grids` (`GET /api/v1/entities/needed-grids`) now populates `CachedStationLookup`'s needed-grids set so `is_needed_grid` contributes once the operator ships the server endpoint (graceful-degrades to inert/empty on 404).

## cqdx logbook endpoint status

`POST /api/v1/qsos` is now **confirmed against the dispensa `cqdx-api.v1` contract** (cqdx PR #126, Q-0007, 2026-06-27): the endpoint returns **HTTP 201 with `{ ok, entity, band, duplicate }`** in both cases — `duplicate: true` when the upload matched an existing contact on the `(userId, callsign, band, mode, startTime)` idempotency key, `false` on a fresh insert. `log_qso` maps `duplicate: true` → `QsoUploadOutcome::Duplicate` (advisory, non-fatal; any 2xx = success) via `QsoUploadBody.duplicate`; the legacy 409 + `{"status":"duplicate"}` paths are retained as defensive fallbacks (cqdx no longer emits them). Validated by `test_log_qso_v1_duplicate_{true,false}_201`.
