# Logging and uploads

## QSO logging — ADIF + SQLite hybrid

`~/.pancetta/qsos.adi` is the durable, append-only ADIF source of truth (vendor-neutral; point WSJT-X / N1MM / LoTW / eQSL at this file directly). `~/.pancetta/qso.db` is a sqlx-backed queryable index rebuilt from the ADIF on startup if missing or stale — safe to delete. `AdifLogWriter` (pancetta-qso) writes ADIF records; `AsyncQsoLogger` (pancetta) persists to both stores. Existing operators auto-migrate: first startup after upgrade exports the legacy DB into a fresh ADIF before flipping over. **TX_PWR** (2026-07-05): `AdifProcessor::qso_to_adif` previously hardcoded `tx_pwr: None` ("not tracked in QSO metadata") — every rendered ADIF record, local or uploaded, always omitted transmit power. `AdifProcessor` now carries a `station_power_watts: Option<f64>` set via `set_station_power_watts`/`with_station_power_watts` (0 = unconfigured, omits `TX_PWR` rather than emitting a literal `TX_PWR:0`); the coordinator stamps it from `config.station.power_watts` at both real construction sites — the ADIF source-of-truth writer (`AdifLogWriter::set_station_power_watts`, coordinator/qso.rs) and the per-QSO upload subscriber (`start_qso_upload_subscriber`, same file — this is what ClubLog/QRZ/eQSL/LoTW/cqdx actually upload) — so it's consistent everywhere, not just at the upload boundary. `async_logger`/`async_database`'s internal SQLite-index rendering and the `pancetta export` CLI command were **not** threaded (no config access at those call sites without a larger signature change; not user-impacting since neither is the operator-facing upload/log-file path) — flagged as a follow-up if ever needed. **Attribution comment** (2026-07-05): `AdifProcessor::qso_to_adif` appends a fixed software-attribution string ("Using cqdx.io & Pancetta -- https://cqdx.io https://github.com/HagaleTechnologies/pancetta") to every QSO's `COMMENT` field, after any operator notes and the Hound "HOUND" marker. Graceful degradation via `append_attribution`/`COMMENT_SOFT_MAX_LEN` (255 chars): full form with URLs when it fits, a short form ("Using cqdx.io & Pancetta") when notes are long, and omitted entirely rather than ever truncating the operator's own notes.

**ADIF import** (PAN-127, 2026-10): `pancetta import <FILE> [--dry-run]` (`pancetta/src/main.rs::import_command`) appends each new contact to `qsos.adi` verbatim through `AdifLogWriter::append_record` (rendered by `AdifProcessor::render_record`: CALL, QSO_DATE, TIME_ON first, then the rest by name; never through `qso_to_adif`, which would reset QSL status to `N` and stamp the attribution comment onto another logger's contacts), fsyncs once, then indexes the new contacts. An existing `qso.db` only gets the new rows, through `QsoDatabase::insert_adif_records` (the record→row conversion `replay_from_adif` uses), because a running station may hold it open and a rebuild deletes the file; a missing one is built with `replay_from_adif`. From before the first write until every new row is indexed, a `qso.db.rebuild` file beside the index (`QsoDatabase::rebuild_marker`) marks it as missing rows; startup rebuilds a marked index and removes the marker only once the rebuild succeeds (a failed one is retried at the next start), because an import stopped between appending and indexing can leave a `qso.db` missing rows yet newer than `qsos.adi`. The new rows commit in one SQLite transaction, so an index never holds part of an import. An import leaves a marker it did not create in place, and keeps its own when `qso.db` was already older than `qsos.adi` (adding the new rows does not repair the old gap, and a later live write could make `qso.db` look current). Planning is pure (`pancetta-qso/src/adif_import.rs::plan_import`): a record is a duplicate when callsign (case-insensitive, suffix-sensitive), band (BAND, else derived from FREQ; empty or pancetta's `NNMHZ` fallback matches any band) and mode (SUBMODE if present, else MODE) match and the start times are at most `DUPLICATE_WINDOW_MINUTES` = 30 apart. Thirty minutes is the tolerance LoTW uses to match one QSO across two logs, and it also absorbs pancetta's CQ-start `TIME_ON` and other loggers' `HHMM` times; repeats within the file are counted separately from contacts already in the logbook. Before the first write, `create_backup` (the PAN-90 helper: exclusive create, `.bak` then `.bak.N`, 0600) copies `qsos.adi`, and the import stops unless the backup starts with the exact logbook bytes the plan was built from (a QSO the running station appends meanwhile only makes it longer); an import that adds nothing makes no backup. Imports are never uploaded: the CLI builds no `QsoManager`, so no `QsoCompleted` fires (the PAN-57 outbox takes live completions only; uploading imported history is follow-on work). A legacy install (`qso.db` without `qsos.adi`) is refused until a start has migrated it. Reader rules (`AdifProcessor::parse_bytes`): a tag tokenizer over the raw bytes (line breaks carry no meaning, a file without `<EOH>` is all records, many records per line), each value cut at its byte count unless only the character count lands just before the next tag (a tag that ends a value is `<EOR>`, `<EOH>` or carries a length, so a lookalike such as `<x>` inside a value does not) (pancetta writes byte counts, WSJT-X-family writers count characters), non-UTF-8 files decoded as Latin-1, `HHMM` times accepted, and one result per record, so a malformed record is reported by position without hiding the rest (`parse_string` keeps its whole-file error for replay). Round-trip guard: a record that does not read back to the same fields through `render_record` → `parse_string` → `record_to_qso` is reported unreadable instead of appended, because one unreadable record in `qsos.adi` aborts the startup index rebuild part-way. Startup ordering: the migrate/rebuild decision (`prepare_local_qso_index`, `coordinator/qso.rs`) now runs before `start_local_qso_log_writers` opens either file. Opening first created an empty `qsos.adi` that made a legacy-only `qso.db` look stale (the rebuild wiped it) and an empty `qso.db` that made a missing index look current (it was never rebuilt).

## Per-QSO online-logbook upload (opt-in)

on `QsoEvent::QsoCompleted`, the coordinator (`pancetta/src/coordinator/qso.rs::start_qso_upload_subscriber`) uploads that single QSO to **ClubLog** (`https://clublog.org/realtime.php`) and/or **QRZ Logbook** (`https://logbook.qrz.com/api`, `ACTION=INSERT`) as one ADIF record (rendered identically to the source-of-truth `qsos.adi` record via `AdifProcessor::qso_to_adif` → `generate_record`), and/or to **cqdx.io** — the operator's own first-party logbook — as the structured `QsoRecord` JSON its `POST /api/v1/qsos` endpoint expects (built from the same `QsoMetadata` via `cqdx_record_from_metadata`, using the dial+offset RF frequency stamped on completed metadata; see `docs/cqdx-api-requirements.md`). ClubLog/QRZ clients live in `pancetta-dx/src/qso_upload.rs`; the cqdx logbook method is `pancetta-cqdx::CqdxClient::log_qso` (defensively parses 201/2xx→`Logged`, 409 or in-band `{"status":"duplicate"}`→`Duplicate`, 401→`Unauthorized`), returning `QsoUploadOutcome`. All three default OFF and require config: `[network.clublog]` / `[network.qrz_logbook]` (validation rejects enabled-without-credentials), and `[network.cqdx]` (`enabled` + non-empty `token`; gate `cqdx_logbook_upload_enabled`). The cqdx logbook upload replaced the old `cqdx_bridge.report_qso` fire-and-forget call in the QsoCompleted handler (no double-upload). Uploads never block/fail the QSO pipeline; a duplicate is non-fatal everywhere. **Pending-upload queue (PAN-57, 2026-10).** ClubLog, QRZ Logbook, eQSL and cqdx.io uploads go through one durable outbox, `~/.pancetta/upload_outbox.json` (`pancetta-dx/src/upload_outbox.rs::OutboxStore`, schema_version 1, pretty JSON, mode 0600, rewritten atomically via `<file>.tmp` + `sync_all` + rename). Each upload is written there *before* its first attempt and removed only when the service accepts it or reports a duplicate; the queue is drained at every start. A file that cannot be read is renamed to `upload_outbox.json.corrupt-<unix-seconds>` (never deleted) and pancetta starts empty; if even the rename fails, the worker keeps state in memory and never overwrites the file that session. The stored payload is the rendered ADIF record (or the cqdx `QsoRecord` JSON, built once at completion so retries hit the same idempotency key); credentials are added by the clients at send time and are never stored. Failures are classified at the client boundary (`DxError::Upload { class, message }`, `UploadFailureClass`, `upload_failure_class_for_status`; the `Display` text is unchanged): **Transient** = 5xx, 408/425/429, timeouts, connection errors, unrecognised responses (`Parse`); **LoginRejected** = 401/403, QRZ `RESULT=AUTH`, an eQSL bad login, cqdx `Unauthorized`/invalid token; **RecordRejected** = any other 4xx, QRZ `RESULT=FAIL`, an oversized 2xx body. Delivery runs in one worker per process (`pancetta/src/coordinator/upload_outbox.rs`, started by the first `start_qso_component` with a destination and reused on Qso restarts, because a crash-restart can briefly leave the old subscriber alive and two writers on one file must never happen). Each destination is a lane with one attempt in flight: transient failures follow `[network.reliability.retry]` (default 3 tries: 0 s, ~1 s, ~2 s, jittered; the section is now validated) and then a 5-minute slow lane; sends are spaced 1 s apart; the lane picks never-tried entries first, then the least recently tried, so one failing entry cannot block the rest. A login rejection stops that destination for the session (config is snapshotted per run) and keeps every upload queued; a record rejection holds that one entry. Held entries are released at every start; nothing is dropped automatically (the operator discards by editing or deleting the file while pancetta is stopped). The queue is capped at 5,000 entries; new uploads past that are refused (the QSO is still in `qsos.adi`). State reaches the operator as PAN-89 readiness-strip **Warnings** (never Blockers, so uploads never hold TX): `⚠ <SERVICE> LOGIN REJECTED`, `⚠ <SERVICE> REJECTED N QSO(S)`, `⚠ <SERVICE> UPLOAD RETRYING · N QUEUED`, `⚠ UPLOAD QUEUE FULL`, each acknowledgeable and listed in Shift+S, plus one Shift+D `qso.upload` row per state change. Delivery is at-least-once and relies on each service's duplicate handling; a crash between a service accepting an upload and the queue write means one benign re-send at the next start. LoTW keeps its single tqsl attempt. Durable receipt states, delivery status in Recent QSOs, explicit restart reconciliation and uploading imported history are follow-on work, not PAN-57. Credentials/tokens stay local and are never logged (target `qso.upload`). **LoTW** and **eQSL** per-QSO upload landed 2026-06-18 (same `start_qso_upload_subscriber` wiring, both default OFF, validation rejects enabled-without-creds): **eQSL** POSTs the rendered ADIF (with `<EQSL_USER>`/`<EQSL_PSWD>` header fields) to `importADIF.cfm`; **LoTW** shells out to the operator's `tqsl` CLI to digitally sign + upload (`tqsl -a all -d -x -u -l "<station_location>" <adi>`; verified live against a real TQSL 2.8.6 install/certificate 2026-09-03, PAN-65 — `-x`/`--batch` is required or tqsl starts its interactive GUI and never exits, accumulating one orphaned window per QSO; the invocation is wrapped in a bounded timeout that kills a hung `tqsl`). Both clients (`EqslClient`, `LotwClient`/`LotwUploadClient`) are in `pancetta-dx/src/qso_upload.rs`; config `[network.lotw]` (`tqsl_path` + `station_location`) / `[network.eqsl]` (`username` + `password`). (The older `pancetta-dx/src/lotw.rs` web-scrape client — QSL download — is a separate concern, left intact.) **QRZ paid XML lookup** (`pancetta-dx/src/qrz_xml.rs`, `QrzXmlClient`): read-side enrichment client (auth→cached session key→callsign lookup for name/grid/dxcc/country/state), `[network.qrz_xml]` (`username`+`password`), default OFF, validation rejects enabled-without-creds. **Wired (2026-06-18) as a gated, best-effort, session-cached grid-enrichment fallback at QSO-completion time** in `start_qso_upload_subscriber` (`coordinator/qso.rs`): on `QsoEvent::QsoCompleted`, when the their-grid is MISSING, `maybe_enrich_grid_from_qrz` looks up the contra-callsign and `merge_qrz_lookup` fills `grids.theirs` with a *valid* (`pancetta_core::GridSquare`-checked) QRZ grid before the ADIF record is rendered, so all downstream uploads carry it; the operator name is appended to `notes` (display/log only). It only fills MISSING fields (never overrides decoded/cqdx data), caches each callsign's hit **or** miss for the session (`Mutex<HashMap<call, Option<QrzLookup>>>`), runs entirely off the hot decode loop (once per completed QSO), and never blocks/fails the pipeline (errors logged at debug, target `dx.qrz`). Network errors from `pancetta-dx` never include the request URL: `DxError::Network` wraps `NetworkError`, which drops the URL when it is built, so a credential or session key sent as a query parameter (QRZ XML, LoTW report download) cannot reach an error message or log line (PAN-100). Disabled → no client built, zero overhead. The subscriber now also spawns when QRZ XML alone is enabled (no upload target required). **cqdx needed-grids**: `CqdxClient::fetch_needed_grids` (`GET /api/v1/entities/needed-grids`) now populates `CachedStationLookup`'s needed-grids set so `is_needed_grid` contributes once the operator ships the server endpoint (graceful-degrades to inert/empty on 404).

## cqdx logbook endpoint status

`POST /api/v1/qsos` is now **confirmed against the dispensa `cqdx-api.v1` contract** (cqdx PR #126, Q-0007, 2026-06-27): the endpoint returns **HTTP 201 with `{ ok, entity, band, duplicate }`** in both cases — `duplicate: true` when the upload matched an existing contact on the `(userId, callsign, band, mode, startTime)` idempotency key, `false` on a fresh insert. `log_qso` maps `duplicate: true` → `QsoUploadOutcome::Duplicate` (advisory, non-fatal; any 2xx = success) via `QsoUploadBody.duplicate`; the legacy 409 + `{"status":"duplicate"}` paths are retained as defensive fallbacks (cqdx no longer emits them). Validated by `test_log_qso_v1_duplicate_{true,false}_201`.
