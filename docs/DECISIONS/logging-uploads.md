# Logging and uploads

## QSO logging — ADIF + SQLite hybrid

`~/.pancetta/qsos.adi` is the durable, append-only ADIF source of truth (vendor-neutral; point WSJT-X / N1MM / LoTW / eQSL at this file directly). `~/.pancetta/qso.db` is a sqlx-backed queryable index rebuilt from the ADIF on startup if missing or stale — safe to delete. `AdifLogWriter` (pancetta-qso) writes ADIF records; `AsyncQsoLogger` (pancetta) persists to both stores. Existing operators auto-migrate: first startup after upgrade exports the legacy DB into a fresh ADIF before flipping over. **TX_PWR** (2026-07-05): `AdifProcessor::qso_to_adif` previously hardcoded `tx_pwr: None` ("not tracked in QSO metadata") — every rendered ADIF record, local or uploaded, always omitted transmit power. `AdifProcessor` now carries a `station_power_watts: Option<f64>` set via `set_station_power_watts`/`with_station_power_watts` (0 = unconfigured, omits `TX_PWR` rather than emitting a literal `TX_PWR:0`); the coordinator stamps it from `config.station.power_watts` at both real construction sites — the ADIF source-of-truth writer (`AdifLogWriter::set_station_power_watts`, coordinator/qso.rs) and the per-QSO upload subscriber (`start_qso_upload_subscriber`, same file — this is what ClubLog/QRZ/eQSL/LoTW/cqdx actually upload) — so it's consistent everywhere, not just at the upload boundary. `async_logger`/`async_database`'s internal SQLite-index rendering and the `pancetta export` CLI command were **not** threaded (no config access at those call sites without a larger signature change; not user-impacting since neither is the operator-facing upload/log-file path) — flagged as a follow-up if ever needed. **Attribution comment** (2026-07-05): `AdifProcessor::qso_to_adif` appends a fixed software-attribution string ("Using cqdx.io & Pancetta -- https://cqdx.io https://github.com/HagaleTechnologies/pancetta") to every QSO's `COMMENT` field, after any operator notes and the Hound "HOUND" marker. Graceful degradation via `append_attribution`/`COMMENT_SOFT_MAX_LEN` (255 chars): full form with URLs when it fits, a short form ("Using cqdx.io & Pancetta") when notes are long, and omitted entirely rather than ever truncating the operator's own notes.

**ADIF import** (PAN-127, 2026-10): `pancetta import <FILE> [--dry-run]` (`pancetta/src/main.rs::import_command`) appends each new contact to `qsos.adi` verbatim through `AdifLogWriter::append_record` (rendered by `AdifProcessor::render_record`: CALL, QSO_DATE, TIME_ON first, then the rest by name; never through `qso_to_adif`, which would reset QSL status to `N` and stamp the attribution comment onto another logger's contacts), fsyncs once, then indexes the new contacts. An existing `qso.db` only gets the new rows, through `QsoDatabase::insert_adif_records` (the record→row conversion `replay_from_adif` uses), because a running station may hold it open and a rebuild deletes the file; a missing one is built with `replay_from_adif`. From before the first write until every new row is indexed, a `qso.db.rebuild` file beside the index (`QsoDatabase::rebuild_marker`) marks it as missing rows; startup rebuilds a marked index and removes the marker only once the rebuild succeeds (a failed one is retried at the next start), because an import stopped between appending and indexing can leave a `qso.db` missing rows yet newer than `qsos.adi`. The new rows commit in one SQLite transaction, so an index never holds part of an import. An import leaves a marker it did not create in place, and keeps its own when `qso.db` was already older than `qsos.adi` (adding the new rows does not repair the old gap, and a later live write could make `qso.db` look current). Planning is pure (`pancetta-qso/src/adif_import.rs::plan_import`): a record is a duplicate when callsign (case-insensitive, suffix-sensitive), band (BAND, else derived from FREQ; empty or pancetta's `NNMHZ` fallback matches any band) and mode (SUBMODE if present, else MODE) match and the start times are at most `DUPLICATE_WINDOW_MINUTES` = 30 apart. Thirty minutes is the tolerance LoTW uses to match one QSO across two logs, and it also absorbs pancetta's CQ-start `TIME_ON` and other loggers' `HHMM` times; repeats within the file are counted separately from contacts already in the logbook. Before the first write, `create_backup` (the PAN-90 helper: exclusive create, `.bak` then `.bak.N`, 0600) copies `qsos.adi`, and the import stops unless the backup starts with the exact logbook bytes the plan was built from (a QSO the running station appends meanwhile only makes it longer); an import that adds nothing makes no backup. Imports are never uploaded: the CLI builds no `QsoManager`, so no `QsoCompleted` fires (uploading history is PAN-57's outbox). A legacy install (`qso.db` without `qsos.adi`) is refused until a start has migrated it. Reader rules (`AdifProcessor::parse_bytes`): a tag tokenizer over the raw bytes (line breaks carry no meaning, a file without `<EOH>` is all records, many records per line), each value cut at its byte count unless only the character count lands just before the next tag (a tag that ends a value is `<EOR>`, `<EOH>` or carries a length, so a lookalike such as `<x>` inside a value does not) (pancetta writes byte counts, WSJT-X-family writers count characters), non-UTF-8 files decoded as Latin-1, `HHMM` times accepted, and one result per record, so a malformed record is reported by position without hiding the rest (`parse_string` keeps its whole-file error for replay). Round-trip guard: a record that does not read back to the same fields through `render_record` → `parse_string` → `record_to_qso` is reported unreadable instead of appended, because one unreadable record in `qsos.adi` aborts the startup index rebuild part-way. Startup ordering: the migrate/rebuild decision (`prepare_local_qso_index`, `coordinator/qso.rs`) now runs before `start_local_qso_log_writers` opens either file. Opening first created an empty `qsos.adi` that made a legacy-only `qso.db` look stale (the rebuild wiped it) and an empty `qso.db` that made a missing index look current (it was never rebuilt).

## Local TX log (PAN-122)

Every frame whose audio the TX worker hands to the audio output is appended to `~/.pancetta/tx-log.jsonl` as one JSON line (`pancetta/src/coordinator/tx_log.rs`; fields and semantics in `docs/CONFIG.md`, "TX log"). It exists because the only per-frame record before it, the TUI's `TxFrameLogged` event, travels the best-effort message bus: headless mode never drains the TUI channel, so once 10,000 TUI-bound messages pile up every event is dropped, and the app log (`tracing_appender::non_blocking`, lossy) has no structured TX record at all. It is distinct from the remote agent's `~/.pancetta/agent-audit.log` (security finding F-12); the two are not merged.

- **Direct call, not the bus (D1).** The TX worker calls `TxFrameLog::append` itself at Step 7. The bus drops silently on a full, missing or disconnected destination (PAN-38), which is exactly the loss being fixed.
- **Path (D2).** `<home>/.pancetta/tx-log.jsonl`, home = `pancetta_home_override` (tests), else `dirs::home_dir()`, else `.`; outside `logs/`, which tracing-appender prunes. Under `cfg(test)` with no override the fallback is `temp_dir()/pancetta-test-home-<pid>`, never a developer's real home.
- **Format (D3).** JSON Lines, schema `v: 1`: `{v, utc, mode, dial_hz, offset_hz, text, origin, qso_id}` (the field set the 2026-09-05 review proposed, plus `v`). `utc` is the same value the TUI event carries. `dial_hz` is the split-aware effective TX dial (`effective_tx_dial`, the resolver the band-plan gate uses), `null` when unknown (0).
- **Durability (D4).** Per batch: serialize into one buffer, `create_dir_all(parent)`, open with `create(true).append(true)`, one `write_all`, `sync_data`; on Unix a best-effort parent-directory `sync_all` after creating a file. No `BufWriter`, no held handle, so a crash right after the append cannot lose the record, and moving or deleting the file never strands a stale handle. `coordinator::tx_log::tests::record_survives_process_abort_immediately_after_append` re-runs the test binary as a child that appends and calls `std::process::abort()`.
- **One writer thread (D5).** A `std::thread` named `pancetta-tx-log` fed by an unbounded `std::sync::mpsc` of jobs, each with a `tokio::sync::oneshot` ack: FIFO, a single writer, and no blocking-pool threads piling up behind a stalled disk. Input is bounded by the physical TX rate (at most one batch per slot), so the queue cannot grow meaningfully. It works on current-thread runtimes, where `block_in_place` would panic.
- **Bounded wait (D6).** The worker waits at most `TX_LOG_ACK_WAIT` = 250 ms for the ack, then logs `TX log: write still pending after 250 ms; …` and carries on; the job stays queued and is written when the disk responds. Step 8's abort/disarm polling therefore starts at most 250 ms late, and PTT release is never blocked. Measured in a Linux container during planning: open + 147 B append + `fdatasync` + close, median 0.075 ms, p99 0.123 ms, max 3.15 ms; the Windows target is expected to be slower, which is why the wait is bounded rather than assumed fast.
- **Only on `Enqueued` (D7).** The record is written inside `Ok(SendIfOutcome::Enqueued)`, before the existing `log_tx_frame` call and with the same timestamp; `Denied`, `Dropped` and refused-before-PTT frames get no record (PAN-134's "denied or dropped audio never appears as aired"), and no suspension was added before the audio enqueue. A bundle is one batch (one fsync), one line per item, one shared `utc`.
- **Fail-open (D8).** A write failure never stops TX: the writer thread logs one `ERROR` per failed batch, `TX log: could not record N frame(s) to <path>: <error>. Frames: [<utc> <mode> <offset> Hz "<text>", …]`, so the app log still holds a copy. Logging is not a Part 97 requirement, and a full disk should not take the station off the air.
- **Rotation (D9).** `TX_LOG_MAX_FILE_BYTES` = 8 MiB, `TX_LOG_ARCHIVES` = 7, `.1` newest: when `len > 0 && len + batch > max`, drop `.7`, shift `.6→.7 … .1→.2`, then active → `.1`. A batch is never split and an empty file is never rotated. A failed rotation keeps appending to the active file rather than losing the record. About 55,000 records per file (~150 B each).
- **Replay (D10).** `--replay` uses `TxFrameLog::disabled()`: no thread, no file (listed in `replay_mode()`'s consumers). `--test-tx` and rig-less dev runs are logged, because their audio does go out.
- **Lifetime (D11).** `ApplicationCoordinator::tx_frame_log` is created by `ensure_tx_frame_log` on the first `start_transmitter_component` and reused on every supervisor restart, so the file never has two writers (the `tx_requeue` shape). Two pancetta processes sharing one home could race rotation; that setup is unsupported.

Limits: `sync_data` cannot see through firmware or OS write-cache lies, so the promise is "survives a process crash; fsync requested for OS crash or power loss". If the disk stalls and the process is killed during the stall, that frame's record can be lost; the `WARN` line marks such windows. Out of scope here: headless mode still never drains the TUI channel (a separate follow-up).

## Per-QSO online-logbook upload (opt-in)

on `QsoEvent::QsoCompleted`, the coordinator (`pancetta/src/coordinator/qso.rs::start_qso_upload_subscriber`) uploads that single QSO to **ClubLog** (`https://clublog.org/realtime.php`) and/or **QRZ Logbook** (`https://logbook.qrz.com/api`, `ACTION=INSERT`) as one ADIF record (rendered identically to the source-of-truth `qsos.adi` record via `AdifProcessor::qso_to_adif` → `generate_record`), and/or to **cqdx.io** — the operator's own first-party logbook — as the structured `QsoRecord` JSON its `POST /api/v1/qsos` endpoint expects (built from the same `QsoMetadata` via `cqdx_record_from_metadata`, using the dial+offset RF frequency stamped on completed metadata; see `docs/cqdx-api-requirements.md`). ClubLog/QRZ clients live in `pancetta-dx/src/qso_upload.rs`; the cqdx logbook method is `pancetta-cqdx::CqdxClient::log_qso` (defensively parses 201/2xx→`Logged`, 409 or in-band `{"status":"duplicate"}`→`Duplicate`, 401→`Unauthorized`), returning `QsoUploadOutcome`. All three default OFF and require config: `[network.clublog]` / `[network.qrz_logbook]` (validation rejects enabled-without-credentials), and `[network.cqdx]` (`enabled` + non-empty `token`; gate `cqdx_logbook_upload_enabled`). The cqdx logbook upload replaced the old `cqdx_bridge.report_qso` fire-and-forget call in the QsoCompleted handler (no double-upload). Uploads are best-effort, spawned per-upload, and never block/fail the QSO pipeline; a duplicate is non-fatal everywhere. Credentials/tokens stay local and are never logged (target `qso.upload`). **LoTW** and **eQSL** per-QSO upload landed 2026-06-18 (same `start_qso_upload_subscriber` wiring, both default OFF, validation rejects enabled-without-creds): **eQSL** POSTs the rendered ADIF (with `<EQSL_USER>`/`<EQSL_PSWD>` header fields) to `importADIF.cfm`; **LoTW** shells out to the operator's `tqsl` CLI to digitally sign + upload (`tqsl -a all -d -x -u -l "<station_location>" <adi>`; verified live against a real TQSL 2.8.6 install/certificate 2026-09-03, PAN-65 — `-x`/`--batch` is required or tqsl starts its interactive GUI and never exits, accumulating one orphaned window per QSO; the invocation is wrapped in a bounded timeout that kills a hung `tqsl`). Both clients (`EqslClient`, `LotwClient`/`LotwUploadClient`) are in `pancetta-dx/src/qso_upload.rs`; config `[network.lotw]` (`tqsl_path` + `station_location`) / `[network.eqsl]` (`username` + `password`). (The older `pancetta-dx/src/lotw.rs` web-scrape client — QSL download — is a separate concern, left intact.) **QRZ paid XML lookup** (`pancetta-dx/src/qrz_xml.rs`, `QrzXmlClient`): read-side enrichment client (auth→cached session key→callsign lookup for name/grid/dxcc/country/state), `[network.qrz_xml]` (`username`+`password`), default OFF, validation rejects enabled-without-creds. **Wired (2026-06-18) as a gated, best-effort, session-cached grid-enrichment fallback at QSO-completion time** in `start_qso_upload_subscriber` (`coordinator/qso.rs`): on `QsoEvent::QsoCompleted`, when the their-grid is MISSING, `maybe_enrich_grid_from_qrz` looks up the contra-callsign and `merge_qrz_lookup` fills `grids.theirs` with a *valid* (`pancetta_core::GridSquare`-checked) QRZ grid before the ADIF record is rendered, so all downstream uploads carry it; the operator name is appended to `notes` (display/log only). It only fills MISSING fields (never overrides decoded/cqdx data), caches each callsign's hit **or** miss for the session (`Mutex<HashMap<call, Option<QrzLookup>>>`), runs entirely off the hot decode loop (once per completed QSO), and never blocks/fails the pipeline (errors logged at debug, target `dx.qrz`). Network errors from `pancetta-dx` never include the request URL: `DxError::Network` wraps `NetworkError`, which drops the URL when it is built, so a credential or session key sent as a query parameter (QRZ XML, LoTW report download) cannot reach an error message or log line (PAN-100). Disabled → no client built, zero overhead. The subscriber now also spawns when QRZ XML alone is enabled (no upload target required). **cqdx needed-grids**: `CqdxClient::fetch_needed_grids` (`GET /api/v1/entities/needed-grids`) now populates `CachedStationLookup`'s needed-grids set so `is_needed_grid` contributes once the operator ships the server endpoint (graceful-degrades to inert/empty on 404).

## cqdx logbook endpoint status

`POST /api/v1/qsos` is now **confirmed against the dispensa `cqdx-api.v1` contract** (cqdx PR #126, Q-0007, 2026-06-27): the endpoint returns **HTTP 201 with `{ ok, entity, band, duplicate }`** in both cases — `duplicate: true` when the upload matched an existing contact on the `(userId, callsign, band, mode, startTime)` idempotency key, `false` on a fresh insert. `log_qso` maps `duplicate: true` → `QsoUploadOutcome::Duplicate` (advisory, non-fatal; any 2xx = success) via `QsoUploadBody.duplicate`; the legacy 409 + `{"status":"duplicate"}` paths are retained as defensive fallbacks (cqdx no longer emits them). Validated by `test_log_qso_v1_duplicate_{true,false}_201`.
