# TX scheduling

## DX-slot-aware TX scheduling

`pancetta/src/coordinator/tx.rs`: WSJT-X-style. Every `DecodedMessage` carries `slot_parity`; the QSO state machine latches `tx_parity = opposite_of(dx_parity)` at QSO start; the TX scheduler picks the next slot of that parity, padding silent samples if early or skip-ahead-cursoring into the modulated waveform if late (up to `tx_late_max_ms`, default 8s). Past that, defers 30s. Never collides with the DX's parity. See `docs/superpowers/specs/2026-04-27-dx-slot-aware-tx-design.md`.

## Half-duplex parity scheduler + always-answer-callers (#39)

`pancetta-qso/src/qso_manager.rs`, `pancetta/src/coordinator/qso.rs`: FT8 is deaf while transmitting, so **every concurrent active QSO must transmit on the same parity** — the opposite 15s window stays free to hear responses; we never TX in sequential windows. Pure `admit_new_qso(current_side, desired) -> TxAdmission::{Admit,Queue}` (idle adopts the side, unpinned desire rides the live side, same-side runs concurrent, cross-side queues — never preempts) + `QsoManager::current_tx_side()` (the parity active QSOs are committed to). Gated into the autonomous `StartAutonomousQso` handler: a cross-parity pounce/CQ is deferred this slot (the DX re-CQs and we re-evaluate once the side clears). **Always-answer-callers**: an always-on decode-loop path (`classify_caller_answer` + `maybe_answer_caller`) answers a station calling us **independent of the autonomous toggle** — `classify_caller_answer` maps a frame directed at us to the reply rung (CqResponse→Report, SignalReport→ReportAck, ReportAck→Rr73, FinalConfirmation→73; compound-aware). Gated by TxPolicy != Disabled + no-active-QSO-with-them (`has_active_qso_with`) + parity-admit + capacity (`max_concurrent_qsos`); it's a *response* not unattended *initiation*, so the FCC presence gate doesn't apply. Carries no failure-backoff, so it also satisfies #43 part 2 (answer a DX that calls us after our initiation watchdog retired the QSO).

## Manual multi-transmit + cross-parity queue (#40)

`pancetta/src/coordinator/qso.rs`: the TX coalescer (`coalesce_transmit_requests`) already multi-streams concurrent same-parity QSOs into one `MultiTransmitRequest`, so selecting 2+ DX in the **same window** runs them at once. The manual `StartQso` handler parity-gates each pick: same/idle side starts immediately; a **cross-window** pick is deferred into `PendingManualCalls` (dedup by callsign, bounded 16) with an operator status line, never preempting a live QSO. `promote_pending_manual_calls` drains the queue when a QSO goes terminal — on completion **after the 45s TX grace** (so the trailing 73 and the new opposite-window call never key in sequential slots) and immediately on failure — adopting the freed side (or the oldest queued call's parity when idle) and starting every matching call; cross-parity ones keep waiting. Pure `partition_pending_calls` split (unit-tested). Operator rule: queue cross-parity, never preempt, flip sides only when the current side's QSOs all finish.

### Multi-TX slow-start fix (2026-06-27)

`coordinator/tx.rs`: the worker used to coalesce the instant the FIRST `TransmitRequest` arrived (~10 ms after pickup), committing the slot to a single stream; sibling openings from serial manual keypresses (each crossing two async hops) landed *after* the batch formed and only joined on the next slot via keep-call rearm — so selecting N same-window DX trickled in one-stream-per-cycle instead of all firing in the first window. (Autonomous never showed it: it enqueues all openings as one tight batch between slots.) Fix: a brief **collection window** (`COALESCE_COLLECT_WINDOW_MS = 800`) before the pickup-coalesce, so same-parity openings batch into one `MultiTransmitRequest`. The window is **absorbed by the Step-6 slot-wait** (PTT keys slightly later; audio still emits at the slot boundary), so it adds no real latency in the common single-QSO case; kept short so a request arriving in the final fraction before its slot is rarely pushed a slot. The coalescer (`coalesce_transmit_requests`, already unit-tested) does the actual multi-fold.

## Drop-stale-TX gate (ended-QSO TX purge)

`coordinator/{mod.rs,qso.rs,tx.rs}`: closes the "we keep TXing every cycle after a QSO ended / only a restart fixes it" bug. The coordinator holds `active_tx_qsos: Arc<RwLock<HashSet<String>>>` (uppercased+trimmed qso ids, keyed via `active_tx_qso_key`). The QSO component keeps it in sync from the `QsoEvent` stream: **inserts** on `StateChanged` into any non-terminal active state; **removes immediately** on `StateChanged` into terminal `Failed` (covers Superseded / UserCancelled / Timeout / SignalLost) and on `QsoFailed`; **removes after a 45s grace** (`COMPLETED_TX_GRACE`, spawned delayed task) on `QsoCompleted` so the final 73 still goes out but leftover backlog is dropped shortly after. (Was 16s — too short: same-parity TX slots are **30s** apart, so a 73 emitted just too late for the immediate next slot defers a full 30s and the 16s grace expired first, silently dropping it — the operator saw us stop at R-report and had to send 73 by hand, observed on-air with G8KHF 2026-06-23. The coalescer keeps newest-per-QSO so only the single 73 is pending, hence a longer grace can't leak stale report frames.) The TX worker (`tx.rs`, helper `tx_qso_is_live`, fails *open* on a poisoned lock) re-checks at the last instant before keying PTT — after the pre-PTT slot sleep and at defer-time — and drops any `TransmitRequest`/`MultiTransmitRequest` item whose `qso_id` is no longer in the set: no PTT, clears the TX strip, sends a failed `TransmitComplete`, logs `target:"tx.policy"` "dropping stale TX for ended QSO …". Requests with `qso_id == None` (manual free-text / tune / test-TX) are never gated. The live-TX indicator is also made unmistakable: bold white-on-red `🔴 TX NOW` chip + frame in `render_tx_strip` for the full ~12.64s the message is keyed, mirrored on the QSO Status panel's "Now:" line (`ui/qso_status.rs::live_tx_for_qso`).

## TX-frequency hold + stuck-DX escape

`pancetta-qso/src/qso_manager.rs`, `states.rs`, `autonomous.rs`: we hold a QSO's TX audio offset for the whole exchange. The offset was always latched once at QSO open into `QsoMetadata.frequency` and reused for every reply/keep-call (the allocator runs only at open); this is now explicit and the only mid-QSO mover is the operator-requested escape: `process_message_for_qso` tracks consecutive *identical* DX frames that do NOT advance the QSO (`QsoMetadata.{last_rx_text,dx_repeat_count}`), and after `DX_STUCK_REPEAT_THRESHOLD` (4) such frames — the DX can't copy our replies, most plausibly a collision on our held offset (FT8 RX decodes the whole passband, so our offset only matters when something steps on it) — hops the offset once via `stuck_hopped_offset` (+300 Hz, wrapping in [300,2700]) and resets the streak. A forward advance resets to 0; a *different* non-advancing frame resets to 1. Applies to Manual and Auto QSOs. Separately, the autonomous collision-listen jitter (`process_collision_listen`) now **holds while a QSO is active** (`active_qso_count>0`) — it only ever seeded the next CQ/opening offset, and only fires from a collision-LISTEN slot (a slot we listened on without transmitting), the "new information" precondition for changing TX frequency.

## Operator TX-offset control + multi-TX de-confliction

`pancetta-qso/src/qso_manager.rs`, `pancetta/src/coordinator/{qso.rs,tui_relay.rs}`, `pancetta-tui/src/{tui_runner.rs,app.rs,ui/mod.rs}`: on a **manual** call/answer (`StartQso`/`RespondToCaller`), our TX audio offset is chosen by priority **held-offset → de-conflict → Tx=Rx (fallback)**, decoupled from the DX's RX freq via the Hound `partner_freq` mechanism. (Operator note 2026-06-28: Tx=Rx is NOT the natural mode — like WSJT-X "Hold Tx Freq", they place their own offset; Tx=Rx is just the no-opinion fallback.) The pure `compute_manual_tx_offset(dx_freq, hold_mode, held_hz, active_offsets) -> (tx_off, Option<partner_freq>)` in `coordinator/qso.rs`: `candidate = (Hold && held!=0) ? held : dx_freq`, then `deconflict_offset(candidate, active_tx_offsets, MIN_TX_SEPARATION_HZ=75, 300, 2700)` (deterministic outward 25 Hz search, no RNG), then `partner = (tx_off != dx_freq).then_some(dx_freq)`. `respond_to_cq_with`/`respond_to_caller` gained a `partner_freq: Option<f64>` param (all other callers pass `None`; `engage_hound` passes `Some(fox_freq)`); `QsoManager::active_tx_offsets()` lists live streams to de-conflict against. **Regression invariant:** Auto + no held offset + no collision ⇒ `tx_off=dx_freq`, `partner_freq=None` ⇒ byte-identical Tx=Rx (guarded by unit + coord_sim tests). Operator sets the held offset with the **`o`** modal (200–2900 Hz; blank=clear→Auto; setting implies `TxFreqMode::Hold`) → `TuiCommand::SetTxOffset` → relay writes `tx_offset_hold_hz: Arc<AtomicU64>` (0=unset) + `tx_freq_mode`; a title-bar "TX off: NNNN (HOLD)" chip shows when held. The completed-QSO RF stamp uses `metadata.frequency` (our real TX offset), correct under Tx≠Rx. Scope: manual path only (autonomous allocator/pounce + Hound unchanged). Spec: `docs/superpowers/specs/2026-06-28-tx-offset-control-design.md`; plan: `docs/superpowers/plans/2026-06-28-tx-offset-control.md`.

## TX-failure operator visibility (2026-07-12)

`pancetta/src/coordinator/tx.rs`: every genuine TX-attempt failure (invalid frequency, encode/modulate error, defensive cursor-exceeded-waveform cases, multi-TX per-item encode error, whole-bundle multi-TX modulation error) used to only `warn!()` to the log file and send a `MessageType::TransmitComplete { success: false, .. }` that **no consumer anywhere in the codebase reads** (grepped — it's produced in `tx.rs` and matched nowhere else). From the operator's view a QSO that can never transmit looked identical to a QSO where the DX just isn't answering — it sat until the manual watchdog (5 min / 25 calls) or the autonomous per-state timeout fired, and the operator had to notice the coincidence and check the log file to learn TX never happened at all. New helper `emit_tx_failure_diagnostic` sends a `Warn`-level `DiagnosticEvent` (target `"tx.encode"`) alongside the existing log line + `TransmitComplete`, so `TX failed: <reason>` shows immediately in the TUI's Diagnostics overlay (Shift+D). Wired into 6 sites across the single-TX and multi-TX paths — including a strictly worse pre-existing gap found in the multi-TX per-item encode loop, where a failed item was silently dropped from `item_texts`/`symbol_sets` with **no** `TransmitComplete` ever sent for it (not even a delayed one). Deliberate policy/security skips (`TxPolicy::Disabled`, stale-QSO-at-defer-time drops, poisoned-arm-lock fail-closed) are deliberately NOT routed through this helper — those are intentional, already have their own operator-visible signal (TX-policy status / the emergency-stop toggle), and aren't the "invisible failure" gap this closes; see the helper's doc comment for the exact boundary. Does not touch QSO-state-machine timeout duration — shortening the wait before declaring a QSO dead (the memory's second, riskier idea) is a separate, deferred design question. Tests: `coordinator::tx::tx_failure_diagnostic_tests` (`tx.rs`).

## Coordinator-level QSO sim harness

`pancetta/tests/coord_sim.rs`: a durable, reusable `CoordSim` fixture that exercises the *coordinator's* TX gate + mock-rig PTT + multi-stream path, complementing the engine-level state-machine harness in `pancetta-qso/src/sim.rs`. It stands up a real `MessageBus`, a real `QsoManager`, a real `MockRig` behind a hamlib consumer (mirror of `coordinator/hamlib.rs`'s `SetPtt` handling), and the *real* shared `active_tx_qsos` set + `tx_policy` atomic. A scenario starts/advances QSOs via the manager's real entry points (`respond_to_cq_with` / `respond_to_caller` / `start_cq`), calls `pump_qso_events()` (a faithful mirror of `coordinator/qso.rs`'s populater — insert on `StateChanged→active`/`QsoCompleted`, remove on `Failed`/`QsoFailed`, forward `MessageToSend`→`TransmitRequest`), then `drive_slot(pending)` which replicates the worker's keying-decision chain — **policy hard-mute → coalesce (real `coalesce_transmit_requests`) → Step-4b gate (real `tx_qso_is_live` over the real set) → key/audio/unkey** — sending real `RigControl(SetPtt)` over the bus to the mock rig and **asserting at the rig level** (`mock.get_ptt() == On`, offset, release). **Determinism**: no `schedule_tx` UTC math and no slot sleep (that's unit-tested in `tx.rs::schedule_tx_tests`); only bounded ms `await`s — pass/fail never depends on wall-clock slot phase. A `Timeline` (keyed / dropped / per-slot offsets, mirroring `sim::Timeline`'s style + Display) carries the readable assertion helpers. Permanent scenarios: PTT-keys-for-scheduled-QSO (StateChanged-at-start fix), stale-TX-dropped-after-supersede (no PTT), coalesce-backlog (newest wins, older not keyed), two-simultaneous-QSOs on distinct freqs, TX-policy Disabled=silent / RespondOnly=in-progress-keys-but-initiation-suppressed / Full=keys, requested-offset-honored, manual-send-never-gated. Made testable by re-exporting `coalesce_transmit_requests` / `CoalesceEntry` / `resolve_required_parity` and widening `active_tx_qso_key` / `tx_qso_is_live` to `pub` from `coordinator/mod.rs` (visibility-only, behavior-preserving).
