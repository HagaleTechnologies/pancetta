## Context: What Was Verified (Read This First)

A prior review claimed the priority scorer's data inputs were "entirely stubbed."
**That claim is wrong.** The wiring chain is intact and was verified end-to-end:

- `CachedStationLookup` implements `WorkedStationLookup` (`pancetta/src/priority_evaluator.rs:77-113`).
- The coordinator constructs the `PriorityScorer` with a clone of the shared lookup
  (`pancetta/src/coordinator.rs:2368-2372`). The clone shares `Arc<RwLock>` fields, so
  updates propagate.
- `CqdxBridge::startup()` populates `needed_dxcc` from `GET /api/v1/entities/needed`
  (`pancetta/src/cqdx_bridge.rs:49-71`); the spot poller populates `rarity_scores`
  from `GET /api/v1/spots?live=true` (`cqdx_bridge.rs:128-145`).
- QSO completion/failure events call `record_worked` / `record_failure`
  (`coordinator.rs:1524, 1545`).
- **API contract verified against the cqdx repo** (`apps/web/src/routes/api/v1/...` and
  `workers/spot-aggregator/src/spot-aggregator.ts`): the `/spots?live=true` envelope IS
  `{ groups: [...] }` (DO snapshot handler, `spot-aggregator.ts:481`), and every required
  field in pancetta's `SpotGroup`/`DxccEntity`/`NeededEntity` deserializers matches the
  server shapes, including nullability (`rarityRank` is the only nullable column in
  `dxcc_entities`; pancetta has `Option<u32>`). **The CLAUDE.md open question
  "response envelope key (groups) unverified against live API" is now resolved — remove
  that note from CLAUDE.md as part of this work.**

What follows are the defects that ARE real. Each has been confirmed by reading the code,
not inferred.

## Defect 1 (highest impact): `is_needed_dxcc` prefix matching is semantically wrong

**Location:** `pancetta/src/priority_evaluator.rs:86-97`

```rust
// The set contains DXCC prefixes (e.g., "3Y/B"), not full callsigns.
// Use prefix matching: callsign "3Y/B1234" matches prefix "3Y/B".
let upper = callsign.to_uppercase();
needed.iter().any(|prefix| upper.starts_with(prefix.as_str()))
```

The `needed` set holds **one representative prefix per DXCC entity** (from
`GET /api/v1/entities/needed`, which returns `prefix` straight from the
`dxcc_entities` table — e.g. `"K"` for USA, `"VE"` for Canada, `"3Y/B"` for Bouvet).
Representative prefixes are display labels, not matching patterns. Consequences:

- **False negatives:** If USA is needed (`prefix "K"`), calls `W1ABC`, `N5XYZ`, `AA4Z`
  never match — most US callsigns don't start with "K".
- **False positives:** `KH6ABC` (Hawaii, ADIF 110), `KL7XYZ` (Alaska, ADIF 6),
  `KP4ABC` (Puerto Rico, ADIF 202) all match `"K"` and would be scored as if they were
  the needed entity (USA, ADIF 291).
- With the 0.35 weight on `needed_dxcc`, this factor — the single largest input to
  autonomous station selection — is effectively noise.

### Fix design

Match on **ADIF entity numbers**, not prefix strings. This requires local
callsign → ADIF resolution.

1. **Generate a Rust prefix table from the same source cqdx uses.**
   cqdx has an authoritative table: `packages/shared/src/dxcc-lookup.ts` (~7,000 lines
   of prefix aliases generated by `scripts/generate-dxcc.ts` from AD1C CTY.CSV), plus
   `matchPrefix()` / `lookupDxccByPrefix()` with special-case handling (KG4/KP1/KP5
   suffix-length rules, before-slash-then-after-slash fallback for portable calls).

   Extend `scripts/generate-dxcc.ts` in the **cqdx repo** to additionally emit a Rust
   source file (e.g. `pancetta-dx/src/dxcc_table_generated.rs`) containing:
   - `static PREFIX_TABLE: &[(&str, u16)]` — (prefix, adif), sorted longest-prefix-first
     (mirror whatever ordering `dxcc-lookup.ts` uses — verify it sorts by descending
     prefix length before porting; if it relies on generation order, make the ordering
     explicit in both outputs).
   - The exact same special-case exceptions as `matchPrefix()` (KG4 length-5 rule etc.)
     must be ported as code in the Rust lookup function, with unit tests mirroring the
     TypeScript tests (`packages/shared/src/__tests__/` — port every DXCC lookup case).

   Single-source generation keeps the two repos from drifting — this was the original
   cross-repo consistency concern and this solves it structurally.

2. **Implement `lookup_adif(callsign: &str) -> Option<u16>` in `pancetta-dx`**
   (new module or replacing the 10-entity sample data in `pancetta-dx/src/dxcc.rs` —
   note the existing `DxccDatabase::load_default_data()` at `dxcc.rs:94` is hardcoded
   sample data and explicitly says "would typically be loaded from a file"; the generated
   table replaces this). Port `lookupDxccByPrefix`'s slash handling verbatim:
   try the part before `/` first, fall back to the part after.

3. **Change `CachedStationLookup.needed_dxcc` from `HashSet<String>` to `HashSet<u16>`**
   (ADIF numbers). `CqdxBridge::startup()` already receives `entityId` in the
   `NeededEntity` response (`pancetta-cqdx/src/types.rs:37-41`) — use that instead of
   `prefix`:

   ```rust
   let needed_ids: HashSet<u16> = needed.iter().map(|n| n.entity_id as u16).collect();
   self.cached_lookup.update_needed_dxcc(needed_ids);
   ```

4. **`is_needed_dxcc` becomes:**
   ```rust
   fn is_needed_dxcc(&self, callsign: &str) -> bool {
       let needed = self.needed_dxcc.read().unwrap();
       if needed.is_empty() { return true; }  // keep conservative policy
       match pancetta_dx::lookup_adif(callsign) {
           Some(adif) => needed.contains(&adif),
           None => false,
       }
   }
   ```

**Tests:** unit tests for the lookup (W1ABC→291, KH6ABC→110, KL7AB→6, F/K5ARH→France,
K5ARH/P→291, VE3XYZ→1, 3Y0J→Bouvet-Peter-I... use real CTY expectations); integration
test that a needed-USA set matches W/N/A/K calls and rejects KH6.

## Defect 2: `worked_on_band` is never seeded from the QSO log, and dup detection ignores band

**Locations:** `pancetta/src/priority_evaluator.rs:77-80`, `coordinator.rs:1445-1470` (QsoLogger init), `coordinator.rs:1524`

Two related problems:

1. **No seeding.** A `QsoLogger` persists QSOs to SQLite at `~/.pancetta/qso.db`
   (`coordinator.rs:1446-1470`), but `worked_on_band` starts empty every run and only
   accumulates `record_worked` calls from the current session. Restart the app and every
   previously-worked station looks new → the -0.40 duplicate penalty never fires → the
   autonomous operator re-works yesterday's contacts.

2. **Band-blind keying.** `is_duplicate(&self, callsign, _freq_hz)` ignores the frequency
   (`priority_evaluator.rs:78`). The field is documented as "worked on the current band"
   but nothing resets it on band change and `record_worked` doesn't record band. A station
   worked on 40m suppresses the same call on 20m — wrong for band-fill hunting (working
   the same station on a new band is a legitimate goal, cf. cqdx's per-band needed API).

### Fix design

1. Key the set by `(callsign, band)`: change `worked_on_band: Arc<RwLock<HashSet<String>>>`
   to `HashSet<(String, String)>` (call, band string like `"20m"`). Add a
   `freq_hz → band` helper (pancetta likely has one already — check `pancetta-ft8` /
   `pancetta-qso::frequency`; if not, port `frequencyToBand` from cqdx
   `packages/shared/src/bands.ts`).
2. `is_duplicate` uses the passed `freq_hz` to derive band and checks `(call, band)`.
3. `record_worked(call, freq_hz)` — signature change; the QSO-completed handler at
   `coordinator.rs:1524` has `metadata.frequency` available.
4. **At startup** (in `start_qso_component` after QsoLogger init), query the log DB for
   all (callsign, band) pairs within a configurable window (default: all time; config key
   `autonomous.dedup_history_days`, 0 = all) and call a new
   `update_worked_on_band(HashSet<(String,String)>)` (the existing bulk setter at
   `priority_evaluator.rs:39` — currently dead code — gets used and retyped).
   Check `QsoLogger`'s schema in `pancetta-qso` for the query surface; add a
   `worked_pairs()` method there if none exists.

**Tests:** dup on same band penalized, same call different band NOT penalized; seeding
test with a fixture DB.

## Defect 3: `recent_failures` never expires

**Location:** `pancetta/src/priority_evaluator.rs:68-70`, populated at `coordinator.rs:1545`

`record_failure` inserts permanently. One failed QSO (band faded, station worked someone
else) penalizes that call -0.15 for the entire session with no decay. The trait method is
named `is_recent_failure` — "recent" is not implemented.

### Fix design

Store `HashMap<String, std::time::Instant>` instead of `HashSet<String>`.
`is_recent_failure` checks `elapsed() < ttl` (config key
`autonomous.failure_backoff_secs`, default 1800 = 30 min). Lazily prune on write (cheap:
prune entries older than TTL inside `record_failure`). No background task needed.

**Tests:** failure penalized within TTL, not penalized after (inject a fake clock or use
a 0-TTL config in the test).

## Defect 4: `is_pota_sota_candidate` flags every compound callsign

**Location:** `pancetta-qso/src/priority.rs:88-94`

```rust
if upper.contains('/') { return true; }   // ← the bug
```

`VK9/W1ABC` (DXpedition prefix), `F/K5ARH` (foreign operation), `W1ABC/MM` (maritime
mobile), `W1ABC/QRP` — all flagged as POTA/SOTA and given the 0.15 boost. Portable-prefix
DX operations are exactly the calls that should be scored by DXCC need/rarity instead.
**Note:** the existing test at `priority.rs:198` (`assert!(is_pota_sota_candidate("VE3/W1ABC"))`)
encodes the wrong behavior and must be inverted, not preserved.

### Fix design

```rust
pub fn is_pota_sota_candidate(callsign: &str) -> bool {
    let upper = callsign.to_uppercase();
    upper.ends_with("/P") || upper.ends_with("/M") || upper.ends_with("/QRP")
}
```

(`/M` mobile is a judgment call — POTA activators commonly sign `/P` or nothing at all.
Do NOT match a bare `contains('/')`.) Longer term, true POTA detection needs spot-source
metadata (POTA spots API), which is out of scope here; note it as a follow-up in the
doc comment.

**Tests:** update `priority.rs:195-201` — `VE3/W1ABC` must now be `false`; add `/MM`
(maritime mobile) → `false`, `/QRP` → `true`.

## Defect 5: `report_spots` silently violates the server's batch contract

**Locations:** `pancetta/src/coordinator.rs:2396-2413` (batch assembly),
`pancetta-cqdx/src/client.rs:75-86`, server: cqdx `apps/web/src/routes/api/v1/spots/report/+server.ts`
+ `packages/shared/src/schemas.ts:118-141`

Verified server behavior:
- `reportBatchSchema` requires `spots: min(1).max(100)`. Pancetta sends one batch per
  15-second slot containing **every decode** — a good band opening produces 30–60 decodes
  per slot; >100 is possible on a wideband SDR. An oversized batch **422s in its
  entirety**.
- Zod validates every element; **one** invalid spot (callsign failing `CALLSIGN_RE`,
  grid shorter than 4 or longer than 6 chars) rejects the **whole batch**. FT8 decodes
  include hashed callsigns (`<...>`) and nonstandard calls that will fail the regex.
- Rate limit: 500 spots/min/user (fine at FT8 rates, but chunking must respect it).
- Failures are logged at `debug!` (`cqdx_bridge.rs:170`) — invisible in normal operation.

### Fix design (client-side, in `CqdxBridge::report_spots` / `client.rs`)

1. **Pre-filter** spots before sending: drop callsigns containing `<`, `>`, or failing a
   basic sanity check (3–15 chars, alphanumeric + `/`); clamp/drop grids not 4–6 chars.
2. **Chunk** into batches of ≤100.
3. Log send failures at `warn!` with the response body (the server returns structured
   `details` on 422 — surface them).

**Tests:** wiremock test with 150 spots → two POSTs; test that an invalid callsign is
filtered client-side rather than sent.

## Defect 6: cqdx startup failure permanently disables the rarity poller

**Location:** `pancetta/src/coordinator.rs:289-316`

If `bridge.startup()` fails once (transient network error at launch, cqdx deploy in
progress), the bridge is dropped: no poller, no rarity, no needed-DXCC for the whole
session — silent degradation to exactly the "stubbed scorer" the original review feared.

### Fix design

On `startup()` error, still keep the bridge and spawn the poller, and spawn a retry task
for the startup fetch (exponential backoff: 30s, 60s, 120s, ..., cap 10 min, forever).
`startup()` is idempotent (pure fetch-and-set). The lookup's conservative empty-set
policy (`is_needed_dxcc` → true when empty) already handles the interim correctly.

**Tests:** simulate first-call failure then success with wiremock; assert needed set
becomes populated after retry.

## Defect 7 (cqdx repo, minor): live mode ignores `band`/`mode` query params

**Location:** cqdx `apps/web/src/routes/api/v1/spots/+server.ts:44-53`

In `live=true` mode only `includeLowConfidence` is forwarded to the DO snapshot;
`band`/`mode` filters are silently ignored (they work in the non-live D1 path).
Pancetta's `fetch_live_spots(band, mode)` accepts and sends both params — today the
coordinator passes `None, None` (`coordinator.rs:300-305`) so nothing is broken, but the
client API is a loaded trap.

### Fix design (pick one, prefer a)

a. **Server:** filter the DO snapshot by `band`/`mode` in the route handler after
   fetching (cheap: the snapshot is already in memory; filter before `json(data)`).
   Note the response is edge-cached with `s-maxage=10` — the cache key must include the
   query params (Cloudflare caches per-URL including query string by default, so this is
   fine, but verify the `Cache-Control` path).
b. **Client:** remove the `band`/`mode` params from `fetch_live_spots` and document that
   live mode is unfiltered.

## Non-defects (do not "fix")

- `rarity()` returning 0.5 for un-spotted calls is correct fallback behavior.
- The conservative empty-set policy in `is_needed_dxcc`/`is_needed_grid` is intentional
  and should be preserved.
- `rank_to_rarity` (types.rs:144-149) is correct for the 1–340 rank scale.
- `needed_grids` is never populated; cqdx exposes `/api/v1/entities/needed-grids` which
  pancetta could wire the same way as needed-DXCC. **Optional follow-up**, not required:
  the empty-set policy makes the factor a uniform +0.20 that doesn't affect ranking.

## Implementation order

Each step is independently landable; this order minimizes rework:

1. **Defect 4** (POTA) — one function + tests, no dependencies. Warm-up.
2. **Defect 3** (failure TTL) — self-contained in `priority_evaluator.rs`.
3. **Defect 1** (ADIF matching) — the big one. Do the cqdx generator change first,
   commit the generated Rust table, then the pancetta lookup + retyped set.
4. **Defect 2** (dup seeding + band keying) — depends on the band helper; do after 1
   so `record_worked` changes land once.
5. **Defect 5** (batch chunking) — client-only.
6. **Defect 6** (startup retry) — coordinator-only.
7. **Defect 7** (live filter) — cqdx repo, independent.

Run `cargo test --workspace` in pancetta and `pnpm test` in cqdx after each step.
Update `CLAUDE.md` (remove the resolved "groups unverified" note) with step 3.
