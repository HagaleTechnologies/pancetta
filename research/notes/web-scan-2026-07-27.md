## Ranked candidates

### 1. hb-268 — MSHV SD FT8 Decoder: Source-code characterization probe (priority 0.45)

**Technique**: MSHV v2.76.5 (released 2026-03-24) added a new "SD FT8 Decoder
(Beta version)" selectable via Menu → Decode → Parameters. The changelog entry
reads verbatim: *"Added: New SD FT8 Decoder (Beta version), can be found in
Menu Decode and his Parameters. Note, not recommended for slow speed PS's"*
(PS = personal computers). The "not recommended for slow processors" caveat
implies meaningfully higher computational cost than MSHV's existing FT8
decoder, and therefore a more exhaustive search algorithm.

**What "SD" likely means**: The changelog does not define the acronym. The
community search surfaced one interpretation consistent with the caveat: "Soft
Decision." In communications parlance, "soft-decision decoder" is a broad term
covering any algorithm that fully exploits soft channel reliabilities (LLRs)
rather than hard-decided bits — potentially a reference to an alternative
LDPC or ML-style decoder, or to a turbo-style iterative approach. A minority
interpretation is "Sequential Decoding" (Fano/stack algorithm on a code
trellis), which would also explain the CPU cost. **The precise algorithm is
undocumented externally**; only the source code can resolve this.

**Primary source**:
- MSHV SourceForge project: https://sourceforge.net/projects/mshv/
  MSHV_2765_Full_Source_Code.zip (2026-03-24, 7.2 MB, GPL-licensed),
  changelog in README.txt (28.3 kB, same archive).
- Note: MSHV v2.76.6 (2026-04-28) is still the latest version. v2.76.6 adds
  only a correction for SNR-dB display in AP7 mode for FT4/FT2; the SD FT8
  decoder itself was introduced in v2.76.5 and retained unchanged in v2.76.6.

**Why not captured in previous scans**: All six prior scans noted "MSHV still
at v2.76.6 (released 2026-04-28)" and moved on, without investigating what was
new *inside* v2.76.5 vs v2.76.4. The SD FT8 decoder was introduced in
v2.76.5 (March 2026), three months before the first weekly scan. This gap is
closed by this entry.

**Measured evidence**: None publicly available. The changelog gives no
sensitivity numbers, benchmark comparisons, or algorithm description. Any
empirical evidence requires either reading the source (algorithm identification)
or benchmarking the compiled binary against known corpora.

**Applicability to pancetta**:
- **If SD = alternative soft-decision LDPC decoder (e.g., min-sum variant,
  normalized/offset MS, or a turbo-style iterate)**: Likely overlaps the
  existing pancetta decoder pipeline (layered BP + OSD). Worth characterizing
  to confirm overlap or identify a distinct approach.
- **If SD = Sequential Decoding (Fano / stack / Viterbi on code trellis)**:
  Potentially a genuinely novel attach point. The FT8 LDPC(174,91) code's
  trellis has 2^83 states (impractical for full Viterbi), but stack/Fano
  sequential decoders are computationally variable — fast on high-SNR inputs,
  slow on weak signals — consistent with the "slow processors" caveat. If
  LZ2HV implemented a partial-trellis or reduced-trellis sequential decoder,
  this would be architecturally distinct from pancetta's current pipeline.
- **If SD = Sphere Decoding**: ML-equivalent for short codes, exponential in
  complexity in the worst case, consistent with the caveat.
- **License/clean-room**: MSHV source is GPL. If the probe reader identifies
  the algorithm and it is worth implementing, a clean-room spec (reader writes
  spec, implementer reads only the spec, never the GPL source) is required per
  project policy.

## Noted but not bank-worthy

### arXiv:2607.15404 — Closed-Loop Bayesian Bandit Encoder with GRAND Receiver (July 16, 2026)

**Technique**: When a channel has an unknown number of on/off interferers
(bursty interference), a closed-loop system: (1) uses GRAND with an HMM-based
soft-decision model that computes per-bit flip probabilities from hidden Markov
model posteriors on the interferer's on/off state, ordering GRAND queries by
HMM posterior; (2) feeds aggregate channel statistics back to a Bayesian
(Thompson sampler) bandit encoder at the transmitter to select between
interleaved and non-interleaved transmission modes.

**Why not bank-worthy**: Two independent reasons. First, the GRAND component's
search target is the random linear code — hb-260 and hb-267 address GRAND for
LDPC codes with 83 and 14 redundancy bits respectively; this paper doesn't
introduce a new query-ordering strategy applicable to those architectures that
isn't already subsumed by hb-267's ORBGRAND reliability-sorted query mechanism.
Second, the HMM noise model is specific to a bursty interference channel (other
users turning on/off), requiring known or learnable interferer state — not the
multipath + AWGN + occasional impulsive noise environment FT8 faces on HF. The
robust LLR territory (hb-256, SHELVED-OPT-IN) already addresses non-Gaussian
HF noise with a different model (alpha-stable impulsive noise). No new bank
entry; confirmed covered.

### arXiv:2607.20130 — Quantum LDPC: Cluster-Based Sequential BP (July 22, 2026)

RL agent selects variable-node clusters to update at each BP scheduling step
for quantum LDPC codes. Quantum-only (stabilizer formalism, degenerate errors);
no classical application. Not applicable. (Fifth consecutive July 2026 scan
with a dominant cluster of quantum LDPC papers; confirmed as a recurring
arXiv pattern for this month.)

### arXiv:2607.14589 — Quasi-BP + Neural Check Nodes for BCH Codes (July 16, 2026)

(Carried from previous scan.) BCH codes, algebraic structure exploited in
quasi-cyclic Tanner graph construction and NN-replaced check-node updates.
Technique specifically exploits BCH polynomial-ring structure; no analogue in
FT8's irregular LDPC code. Not applicable, not bank-worthy.
