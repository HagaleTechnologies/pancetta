## Status updates on open items from prior scans

### hb-271 — WSJT-X 3.2.0-rc1 standard-decoder changes: implementable specifics now available

mfsk-core issue #435 ("Audit vs WSJT-X 3.2.0-rc1") provides the specific mechanism
details not available in the Sep 28 scan. The changes apply to the STANDARD FT8 decoder
(`ft8b.f90`), distinct from the `ft8var` multithreaded decoder also captured in hb-271.

**New specifics from issue #435:**

1. **AP pass doubling mechanism (implementable)**: Each AP type now runs with BOTH
   `nsym=1` (`llra`) AND `nsym=2` (`llrb`). Previously each AP type ran once with one
   LLR variant. The doubled pass covers both single-symbol and two-symbol coherent LLR
   variants (per `spec-wsjtx-mainline-ft8b.md:200-205`: `nsym=2` maps to `bmetb`/`llrb`;
   `nsym=3` maps to `bmetc`/`llrc`), giving each callsign hypothesis two decode
   opportunities at different demodulation depths.
   This is architecturally compatible with pancetta's AP infrastructure.

2. **apmag scaling change (implementable)**: Scaling shifted from
   `maxval(abs(llra))*1.01` to `apmag = maxval(abs(llrz))*1.1` per pass. Uses the
   freshest LLR vector (`llrz`) rather than the initial AP LLR (`llra`), and scales
   more aggressively (1.1 vs 1.01). Effect: reduces LLR saturation accumulation across
   chained AP passes.

3. **ndepth==2 OSD cap removed (implementable)**: The upstream decoder removes an
   additional constraint that was forcing `maxosd=0` in certain pass contexts at
   `ndepth<=2`. Per the existing spec (`spec-wsjtx-mainline-ft8b.md:303-307`),
   `maxosd=0` means "BP + 1 OSD with channel LLRs" (not no OSD); the effective change
   is that those pass contexts can now reach higher OSD depth (`maxosd > 0`). Verify
   the exact scope of the removed constraint before implementing.

4. **sync8 `mlag` widening**: Lag search window widened from 10 to 13 sync-surface columns
   (0.04 s each, per `spec-wsjtx-mainline-sync8.md:92-95`), widening the timing search
   from ±0.40 s to ±0.52 s. Increases timing robustness for signals with non-standard
   propagation delays.

5. **Hard sync quality threshold raised**: The Costas-match count threshold `nsync`
   (integer, 0–21 max; defined in `spec-wsjtx-mainline-ft8b.md:181-185`) is now
   dynamic: reject if `nsync <= 6` (normal), `nsync <= 7` for `imetric==2`, or
   `nsync <= 8` for `ndepth<=2`. This is the hard pre-decode reject on the integer
   Costas match count — distinct from the normalized per-pass `syncmin` threshold
   (1.3–2.0; `spec-wsjtx-mainline-ft8-decode.md:99-103`). Applying 6–8 to `syncmin`
   would reject essentially every candidate; keep these values at the `nsync` stage.

6. **SNR floor**: Unchanged at −24.0 in mfsk-core's Rust implementation (the Sep 28
   scan's "−25.0" figure was a search-snippet artifact).

**Action for hb-271**: These specifics make items (1)–(3) independently implementable
without the full ft8var audit. Suggest opening sub-hypothesis or experiment ticket for
the AP-doubling + apmag combination, which can be tested in one session using the
existing eval harness.

**Community benchmarks**: WSJT-X 3.2.0-rc1 is 11 days old (as of this scan). No
on-air sensitivity comparisons vs the standard decoder found yet. Continue monitoring.

### hb-269 — RBE (arXiv:2608.09560): paper now accessible; diversity transfers to short non-5G codes

arXiv:2608.09560 ("Row-Boosted Ensemble Belief Propagation for Short LDPC Codes",
Bezner, Krieg, ten Brink; Stuttgart; Aug 2026) is now accessible via HTML on arxiv.org,
resolving 5 consecutive proxy-block weeks.

**Key findings from abstract + search-extracted content:**

- **Diversity mechanism**: all ensemble members share the SAME parity-check matrix H and
  the SAME BP kernel; they differ only in a small set of rows whose outgoing messages
  are "boosted" (scaled up). No re-encoding, no permuted H. The ensemble is minimal:
  each member adds one boosted-row variant to a base decoder.

- **FER numbers on primary target (5G NR BG1 (144,96) code)**:
  BP-20 (20 iterations) frame-error rate at Eb/N0 = 4.0 dB: 1.6×10⁻² → 1.6×10⁻³
  with RBE (32 members). One order of magnitude FER gain on a 144-bit code.

- **Transfer claim**: authors state gains "transfer across 5G NR block lengths and rates,
  to non-5G short LDPC codes, and across flooding and layered schedules." This directly
  addresses the diversity-premise probe question for hb-269: whether graph diversity
  exists in short, optimized irregular LDPC codes.

- **Key caveat for FT8 applicability**: the paper's cross-code experiments (§IV-D,
  arXiv:2608.09560) include codes as short as MET (100,50) and CCSDS (128,64) — both
  shorter than FT8's LDPC(174,91). This strengthens the transfer prior. However,
  FT8's LDPC(174,91) was designed specifically for the FT8/FT4 modes (per the QEX
  protocol paper, not WiMAX-derived); its structure and optimization target differ from
  the 5G NR QC-LDPC and MET/CCSDS families tested in the paper. The transfer claim
  is a qualitative author claim, not a measurement on LDPC(174,91). The diversity probe
  (hb-269 experiment) remains the correct next step.

**Status update for hb-269**: Upgrade from BLOCKED (proxy) to PENDING. The paper's
diversity-transfer claim provides a positive prior for the probe, but the probe must
validate on FT8's specific code graph. The probe design (per `web-scan-2026-08-24.md:123-136`):
run 32-member RBE on the eval harness's hard-200 tier; measure FER delta vs
single-decoder baseline; pass the noise_1000 zero-tolerance false-positive gate (32
members vs 1 decoder means more codeword paths and a larger false-decode risk); and meet
the production-budget wall-clock run constraint. The existing hb-269 plan specifies all
three gates — do not reduce the probe to only an FER comparison.

## Noted but not bank-worthy

### Decodium 4.0 Core Shannon (github.com/iu8lmc/Decodium-4.0-Core-Shannon)

**What it is**: A fork of WSJT-X focused primarily on FT2 mode (a ~3.2–3.75-second
slot digital mode using LDPC(174,91) FEC with a multi-pass "Raptor-style" decoder engine,
developed by IU8LMC from ft2.it; slot time per `pancetta-ft8/src/protocol.rs:234-254`
and `research/specs/catalog-mshv.md:176-182`; FEC per `pancetta-ft8/src/acceptance.rs:61-63`). Active development through
Oct 3, 2026 (v1.0.660). The "Shannon" name refers to the decoder engine.

**FT8 claims investigated**: Issue #87 reports user-observed FT8 sensitivity of −24 dB
SNR; the project's own specs claim −21 to −23 dB for FT8 in various release versions.
The −24 dB claim appears to be a user surprise report (better-than-advertised result in
a single session), not a controlled benchmark.

**Decoder techniques found in release notes**: AP decoding with known callsigns (QSO-state
AP, similar to ft8var/hb-271's hint decoder), signal subtraction with long (2000-sample)
FIR filter, asynchronous multi-signal subtraction and retro sweeps. No mention of OSD,
ensemble BP, neural approaches, or modifications to LDPC(174,91) decoding. The DEEP mode
sensitivity claims are for FT2's Raptor 5-pass decoder, not for Decodium's FT8 path
(NMS-20, per Sep 14 scan: `research/notes/web-scan-2026-09-14.md:100-104`).

**Assessment**: Not bank-worthy. The techniques are variants of QSO-state AP (hb-048/
hb-271) and signal subtraction (hb-086/hb-089 family, both shelved). No novel LDPC
algorithm. The −24 dB FT8 claim is uncontrolled and inconsistent with the software's
own advertised specs. The project is an FT2-mode transceiver, not an FT8 decoder research
project. License: **GPL v3** (verified in Sep 14 scan: `research/notes/web-scan-2026-09-14.md:109-115`);
clean-room spec firewall applies (`docs/PROVENANCE.md:23-30`).
