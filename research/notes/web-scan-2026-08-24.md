## Ranked candidates

### 1. hb-269 — Row-Boosted Ensemble BP (RBE) for short LDPC codes  (priority 0.50)

**Technique**: Row-Boosted Ensemble (RBE) decoding runs K copies of the
same BP kernel on the same parity-check matrix H, where each member boosts
the outgoing messages from a distinct small subset of parity-check rows by
a learned or heuristic scalar factor. All K members share the identical H
and the same flooding/layered schedule; they differ only in *which rows*
are boosted and *by how much*. A valid codeword from any member (CRC check)
is accepted as the decode; if multiple pass, the one with best channel
metric is chosen.

**Why this is distinct from existing bank entries**:
- **aSCED** (affine subcode ensemble; draft-numbered hb-261 in the Jun 15
  scan, hb-262 in the Jun 22 scan — numbering unresolved until bank
  update; canonical bank ends at hb-260): creates diversity by row-masking
  H to derive per-member subcodes (reducing the active parity checks), plus
  optional coset shifts of the codeword estimate before syndrome checking —
  H itself is not modified. RBE keeps H unchanged and adds no coset shifts;
  diversity comes from message-level row boosting. The paper explicitly
  benchmarks RBE against affine subcode ensembles at equal K and shows RBE
  wins.
- **hb-257** (parallel ensemble + ML selection): covers parity-check
  basis diversity, automorphism permutations, schedule diversity, noise
  injection, and saturated BP — see hypothesis_bank.md lines 6819-6825.
  The June 15 scan note also notes hb-257 was intended as a pointing stub
  to be superseded by a concrete SCED entry (hb-261, Jun 15 scan).
  RBE's row-boosting (fixed H, per-row message scaling) is a distinct
  mechanism not covered by any of hb-257's enumerated axes.
- **hb-254 / saturation-perturbation retry**: serial multi-round BP where
  failed VNs are perturbed. RBE runs all K members in parallel from the
  same received word; no iterative identification of "bad" VNs is needed.

**Primary source**: arXiv:2608.09560, Paul Bezner, Felix Krieg, Stephan
ten Brink (Universität Stuttgart). Submitted 2026-08-10.
URL: https://arxiv.org/abs/2608.09560

**Measured evidence** (from web search result excerpts; direct arXiv fetch
and HTML render blocked by proxy — full paper not yet obtained; see gaps):
- 5G NR BG1 code (n=144, k=96, rate ≈ 0.67): RBE-32 vs BP-20 at
  Eb/N0 = 4.0 dB: FER 1.6×10⁻² → 1.6×10⁻³ (10× reduction). [unverified
  against figure; from search excerpt]
- RBE-32 outperforms affine-subcode ensemble (aSCED) at equal K=32.
  [search excerpt]
- RBE-32 outperforms saturated-min-sum at equal K=32. [search excerpt]
- Gains transfer across code lengths, rates, and BP schedules claimed in
  abstract; experimental coverage unknown until full paper is obtained.

**Applicability to pancetta**:
- FT8 uses LDPC(174,91) — a short LDPC code in the same class. The BG1
  (144,96) benchmark is slightly higher-rate (0.67 vs 0.52 for FT8) but
  comparable blocklength; actual gain on FT8's LDPC(174,91) (rate 0.52 vs
  0.67) is graph- and absorbing-set-dependent and must be measured directly.
- Pancetta already runs layered BP (sum-product, 100 iterations); RBE
  extends this to K parallel instances. Wall-clock impact is O(K) on the
  LDPC step but LDPC is not the current bottleneck (sync/FFT dominate).
- Row selection strategy and boost-factor construction are **key unknowns**
  (full paper not yet obtained; see gaps). The heuristics "random /
  highest-degree / absorbing-set-adjacent" listed in the draft bank entry
  are speculative alternatives to try pending paper access, NOT the
  published RBE algorithm. Probe should be gated on first obtaining the
  paper to verify the row-selection method and whether training is required.
- FP safety: each of the K ensemble members independently passes CRC, so
  wrong-codeword convergence gets K chances to produce a CRC collision. The
  probe plan must include a `noise_1000` (or equivalent noise-only) FP gate
  alongside the hard-200 TP measurement — consistent with hb-252's lesson
  (hb-252's FP-dominated re-open attempts documented this failure mode).

**License**: Academic. No GPL firewall required; implement directly from
paper equations.

## Noted but not bank-worthy

### arXiv:2608.14280 — LLM-Assisted LDPC Decoding via Syndrome-Verified Semantic Priors (August 14, 2026)

**Technique**: When BP fails to decode a natural-language payload, a large
language model infers intended characters from semantic context. Rather than
trusting LLM outputs directly, the system validates each predicted
correction against parity-check syndrome constraints, then injects only
verified corrections as soft LLR updates before re-running BP.

**Why not bank-worthy**: Requires a **natural-language** payload: the LLM
exploits semantic structure in byte-level text (character n-grams,
word embeddings). FT8 messages are highly structured (callsign1 callsign2
grid/report/rrr73 — 77 bits total) but not natural language; an LLM has
no useful semantic prior for "W1AW/W8 N9TZK FN43" as English text. The
syndrome-verification mechanism is independently interesting but is
functionally equivalent to AP decoding (a priori), which already exists
in pancetta and WSJT-X: AP injects known-callsign priors as LLR perturbations
and accepts only candidates that pass the syndrome. No new mechanism.
Additionally, LLM inference at decode time is incompatible with FT8's
real-time 15-second window constraint. Not bank-worthy; documented here to
prevent future resurface.

below for follow-up.

### wsjtr (KC1WIH, Brian Bodiya) — cross-sequence AP, 1% supplemental decodes

wsjtr is a Rust FT8 decoding library that runs alongside WSJT-X and reports
supplemental decodes (found by wsjtr but not WSJT-X). The technique: use
callsigns decoded in one T/R sequence as AP priors for the next, generate
candidate messages, correlate against residual audio with a distance-metric
acceptance threshold. A Feb 2026 wsjt-devel thread measured "+1% improvement
over WSJT-X a7 at +10% CPU cost."

Not bank-worthy: the cross-sequence callsign-prior mechanism is the exact
architecture of hb-237 (cross-sequence A7, hypothesis_bank.md line 6383),
which explicitly names wsjtr as the reference implementation. (Note:
hb-173 is the within-QSO pair-conditional context graph covering later
exchange turns, not the cross-window prior-sequence correlation.)
**Correction to hb-237 status**: hb-237 has been implemented and measured
negative. Batch 54 (`research/notes/2026-06-09-batch54-hb237-trust-gated.md`):
trust-gated cross-sequence ON = +0 TPs / +796 FPs; decision "Keep
default-OFF". Batch 67 (`research/notes/2026-06-09-batch67-hb237-real.md`):
real-data probe = +0 TPs / +1233 FPs. Status: MEASURED-NEGATIVE / default-OFF
(not PROPOSED-FROM-RESEARCH as the hypothesis bank entry says). The wsjtr
+1% figure may reflect a different operating corpus or trust model; it does
not contradict pancetta's own measurement.
