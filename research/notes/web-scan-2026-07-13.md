## Ranked candidates

### 1. hb-267 — Two-Stage BP+GRAND-on-CRC Outer Code (priority 0.35)

**Technique**: When LDPC belief-propagation fails to find a valid codeword,
run ORBGRAND (Ordered Reliability Bits GRAND) on the *CRC outer code* rather
than on the full LDPC code. The CRC outer code for FT8 is CRC(91,77): the
77-bit payload is protected by a 14-bit CRC, giving a 91-bit codeword before
LDPC encoding. ORBGRAND queries error patterns on these 91 bits in decreasing
channel-reliability order (lowest-magnitude |LLR| bits first), checks the
CRC-14 polynomial for each candidate, and for any CRC-passing pattern,
encodes the 77 information bits back into LDPC to verify against the received
channel vector. The output is the most-probable LDPC codeword among all
CRC-passing GRAND candidates.

**Why this is architecturally distinct from hb-260 (GRAND DEAD END)**:
hb-260 closes GRAND applied directly to the LDPC code, which has **83
redundancy bits** — far outside GRAND's tractable guessing regime ("query
counts explode at weak-signal SNRs"). The new proposal applies GRAND to the
**CRC outer code, which has only 14 redundancy bits**. ORBGRAND with 14
check bits requires only O(91^k) queries at error weight k; at the SNR
range where BP fails on FT8 (~−20 to −16 dB), k ≤ 3 suffices for a large
fraction of failures ({91 choose 3} = 117,480 worst-case, orders-of-magnitude
fewer than GRAND on the 174-bit LDPC code). The paper demonstrates that a
budget of Q=20 GRAND queries outperforms 50 MSA iterations for LDPC-CRC
concatenated codes.

**Relation to pancetta's OSD**: OSD and GRAND-on-CRC are orthogonal search
strategies over the same target space. OSD selects the 91 most-reliable
positions *from the full 174-bit LDPC codeword*, applies Gaussian elimination
to find a systematic form, then flips combinations among those positions.
GRAND-on-CRC operates directly on the 91-bit soft-hard estimate of the
systematic portion *without Gaussian elimination*; its search order is
governed by individual |LLR| magnitudes. They can recover different candidates
when OSD's MRP basis (174-bit) and GRAND's 91-bit soft-estimate disagree on
which bits to try first. OSD contributes essentially zero recall on
pancetta's hard-200 corpus (hb-014); a probe of GRAND-on-CRC may find
different failing-mode survivors.

**Primary sources**:
- "An Efficient Two-Stage Decoding Scheme for LDPC-CRC Concatenated Codes,"
  Kong, Liu, Shi, Miao; *Entropy* 27(9):899, 2025-08-25.
  DOI: 10.3390/e27090899; PMC:12468592.
  Key result: **MSA15-GRAND20 achieves better BER/FER than MSA50** — 15 BP
  iterations + 20 GRAND queries on the CRC code outperforms 50 BP iterations
  alone, with lower average complexity.
- "CRC-Aided Guessing Codeword Decoding for Short Blocklength," preprint,
  TechRxiv, 2026-02-13. DOI: 10.36227/techrxiv.177102163.30933787.
  Companion paper specifically targeting the LDPC+CRC architecture with
  GCD (Guessing Codeword Decoding) guided by CRC verification.

**Measured evidence**:
- Entropy paper: MSA15-GRAND20 outperforms MSA50 (exact dB numbers blocked
  by proxy; abstract confirms better BER and "relatively low average
  complexity"). For FT8's SNR regime the BP stage already converges on strong
  candidates; GRAND handles the residual BP-failing population with few
  queries.
- ORBGRAND's tractability for 14-redundancy-bit codes at low-to-moderate SNR
  is established in the foundational GRAND literature (Duffy, Médard; Wan &
  Zhang 2024); Q=20–100 queries covers most practical error weights.

**Applicability to pancetta**:
- **Attach point**: `pancetta-ft8/src/ldpc.rs` or `decode.rs`. When the
  existing `ldpc_decode` + `osd_decode` pipeline fails: extract the 91-bit
  systematic portion (soft-hard decisions), run ORBGRAND against the CRC-14
  polynomial (`pancetta-ft8/src/crc.rs` already implements CRC-14), for each
  CRC-passing candidate encode the 77 info bits back to 174-bit LDPC and
  compare likelihood against the channel soft output.
- **Existing assets**: CRC-14 checking is already implemented. The LDPC
  encoder (the transpose of the parity-check process) needs a small companion
  function (~30 LOC) to map 77 info bits → 174-bit LDPC codeword for
  verification.
- **Query budget**: parameterise Q (default 50 queries; increase only if
  kill-switch passes). Wall-clock cost: Q × (CRC check + encode) + occasional
  LLR comparison. Each ORBGRAND query is ~300 ns; Q=50 adds ≤15 µs per
  BP-failing candidate — negligible vs the existing LDPC pass (>1 ms/candidate
  at 100 iterations).
- **No ML training required**: ORBGRAND is deterministic, driven entirely by
  the sorted-|LLR| ordering of the 91 soft bits.
- **Distinct from hb-260**: The 14-redundancy-bit CRC outer code is tractable;
  the 83-redundancy-bit LDPC code is not. The architecture avoids the failure
  mode hb-260 documented.
- **Concern**: pancetta's hb-014 finding shows OSD contributes near-zero
  additional recall on the hard-200 corpus. If BP-failing candidates are
  generally too far from any codeword for either OSD or GRAND-on-CRC to find
  them (i.e., the signal is genuinely lost, not just in a trapping set), the
  gain may be zero. The probe targets this uncertainty directly.

**License**: Entropy (MDPI open-access); TechRxiv preprint. Both are
academic; no GPL source consulted. Implement from published equations only.

## Noted but not bank-worthy

### SOGRAND check node update for LDPC (arXiv:2607.04045, July 4, 2026)

**Technique**: Specializes the SISO computation of SOGRAND (Soft Output
GRAND) to Single Parity Check (SPC) codes, yielding two alternative check
node (CN) update rules for LDPC belief propagation.

**Why not bank-worthy**: The paper's measured results are described as
"similar or better" than Gallager's sum-product and normalized min-sum —
with the two proposed CN update rules giving "essentially identical" results
to each other, with α=0.9 scaling having only a minor impact. This is
indistinguishable from pancetta's existing normalized min-sum (which also
uses a tunable α). The paper is primarily a hardware-efficiency paper
(low-complexity, hardware-friendly CN arithmetic), not a decoding-sensitivity
improvement. Testing was on 5G NR LDPC codes (medium-to-long), not on short
codes like FT8's (174,91). No specific dB gain is quantified for short-block
performance. No bank entry; document here to preempt future resurface.
