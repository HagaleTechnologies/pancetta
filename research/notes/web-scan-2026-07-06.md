## Ranked candidates

### 1. hb-264 — Adaptive Per-Word Weighted BP (parallel variant) (priority 0.38)

**Technique**: Run K parallel weighted belief-propagation (WBP) decoders on the
same LLR vector, each using a *different per-edge normalization weight vector*
{w_1 … w_K}. Each WBP decoder runs the existing layered-BP schedule, but every
check-to-variable message is multiplied by the edge's weight ω_{i,j} before
being passed. The weight vectors are sampled from a discrete set empirically
chosen to diversify the decoder's fixed points on the Tanner graph, escaping
trapping sets that defeat a single static weight assignment. The ensemble output
is the union of all CRC-passing decodings across K paths. A simpler "two-stage"
variant trains a small MLP on BP trajectory features to *predict* the best weight
vector per received word, reducing the K-path fan-out to a single adaptive pass.

This is architecturally DISTINCT from SCED (arXiv:2501.11993, proposed
hb-262): SCED diversifies by flipping LLR **signs** at the input; APWBP
diversifies by varying edge **weights** during message-passing. Both attack
trapping-set fixed points, but through orthogonal Tanner-graph perturbations.
They can be composed: SCED as the LLR-input perturbation + APWBP as the
message-passing perturbation, for a two-level ensemble.

**Source**: arXiv:2507.19941, "Adaptive Learned Belief Propagation for Decoding
Error-Correcting Codes," Alireza Tasdighi and Mansoor Yousefi (July 2026).
Published simultaneously to PMC:12386122. This is a **July 2026 preprint** —
the most recent paper found in this scan and genuinely new since June 22.

**Measured evidence**:
- BER up to **one order of magnitude less** than static WBP at the same
  decoding complexity, across BCH, polar, and QC-LDPC codes over AWGN.
- Optical-fiber application: 0.8 dB coding gain vs. neural normalized
  min-sum decoder at equivalent complexity and latency.
- The parallel-variant (K discrete weight vectors) achieves these results
  without a trained neural network; the two-stage variant requires a small MLP
  but adapts per word, giving additional gain at low K.

**Applicability to pancetta**:
- **Attach point**: `pancetta-ft8/src/ldpc.rs`, the `LdpcDecoder` struct's
  inner flooding/layered loop. Replace the current fixed normalization factor
  (the `alpha` parameter in normalized min-sum) with a per-edge weight ω_{i,j}
  sampled from a K-element discrete set.
- **Data already available**: `Ft8Config::ldpc_iterations` and the existing
  `rayon`-parallel candidate loop already fan out; adding K parallel WBP
  paths per candidate is ~40 LOC inside the LDPC loop.
- **No NN required for the parallel variant**: generate K weight vectors
  offline (e.g., K=8 random draws from {0.7, 0.85, 1.0, 1.15, 1.3}^E where
  E = number of edges in the Tanner graph) and hard-code them as a static
  array. Pairs the existing `layered_bp` path with K differently-scaled
  check-node updates.
- **FT8 LDPC(174,91) structure**: QC-LDPC codes were explicitly tested in the
  paper. FT8's code is irregular but structurally similar (variable node degrees
  2–5, check node degrees 5–8). The trapping-set landscape benefits from edge-
  weight diversification.
- **Synergy**: composable with proposed SCED (hb-262) — SCED perturbs LLR
  inputs, APWBP perturbs edge weights; combining the two gives a two-level
  ensemble that may escape trapping sets that resist either alone.
- **Scope**: parallel variant ~60 LOC in `ldpc.rs` + a constant array of K
  weight vectors (pre-computed, no per-run overhead). Two-stage variant adds
  a small offline training step (out of scope for an initial probe).

**License**: Academic preprint (arXiv:2507.19941), no GPL; implement from
equations and published weight-generation scheme only.

Status: PENDING
Priority: 0.38
Source: arXiv:2507.19941 "Adaptive Learned Belief Propagation for Decoding

Premise: A single static per-edge normalization (pancetta's `alpha` in

Expected gain: BER order of magnitude vs static WBP (paper); 0.8 dB vs neural
NMS on optical channel. Hard-200 translation uncertain — apply K=4 kill-switch
first.

Architecture: ldpc.rs — K parallel normalized-min-sum passes per LDPC-failing
candidate, each with a different edge-weight vector. Static K-element array of
weight matrices pre-generated offline. Union with existing CRC-passing
decodings; dedup via existing callsign-continuity filter.

Relationship to hb-262 (SCED): complementary not competing. SCED perturbs LLR
inputs; APWBP perturbs edge weights. Can combine: each SCED path runs K APWBP
decoders for a K×S ensemble at cost K×S× per-candidate LDPC time.

Probe plan:
1. Pre-generate K=4 edge-weight vectors from {0.75, 0.875, 1.0, 1.125}^E

2. For each sync candidate that fails single-path BP+CRC: run K=4 WBP
   variants, collect CRC-passing union.
3. Kill-switch: Δrec < +5 on hard-200 at K=4 → CLOSE.
4. If kill-switch passes: sweep K ∈ {4, 8, 16}; graduate at elbow ≥ +20 TPs.

Graduation rule: ΔTPs ≥ +20 on raw_530_full with ΔFPs ≤ +50 at K=8.

### 2. hb-265 — NED/SED ensemble variants from the comparative short-LDPC study (priority 0.30)

**Technique**: arXiv:2410.23980 (Krieg, Clausius, Geiselhart, ten Brink; Oct 2024)
provides the first head-to-head comparison of all ensemble decoding methods for
**short-length LDPC codes**, covering:

- **MBBP** (Multiple-Bases BP): different sparse parity-check sub-bases per decoder
- **AED** (Automorphism Ensemble Decoding): permutation-group diversification
- **SED** (Scheduling Ensemble Decoding): each decoder uses a different **layered
  BP update order** (permutation of the layer traversal sequence)
- **NED** (Noise-Aided Ensemble Decoding): adds small Gaussian noise
  ε ~ N(0, σ²) to each LLR before BP; K different noise realizations per candidate
- **SBP** (Saturated BP): related to hb-254's saturation/perturbation retry

Two candidates are actionable for pancetta:

**SED** is the cheapest to implement: pancetta already has layered BP (hb-063,
GRADUATED). SED simply permutes the order in which layers are processed between
K parallel decoders. Per the paper, SED performs below MBBP/AED on codes with
known structure, but for the FT8 LDPC(174,91) code (unknown automorphism group,
which is why MBBP/AED are hard), SED may be the best structurally-free option.

**NED** is complementary to SCED (hb-262): where SCED applies a ±∞ binary sign
flip to a random subset of LLRs, NED applies a bounded Gaussian perturbation to
ALL LLRs. NED is a "softer" randomization that may help when trapping-set fixed
points are shallow (narrow basins), while SCED helps when they are deep (LLR
sign reversal needed to escape). They can be composed.

**Source**: arXiv:2410.23980, "A Comparative Study of Ensemble Decoding Methods
for Short Length LDPC Codes," F. Krieg et al. (October 2024, published in IEEE
via ICCIT 2024). Also: ieeexplore.ieee.org/document/10949101/.

**Measured evidence**: The paper compares all five methods on short LDPC codes.
Methods exploiting code structure (MBBP, AED) typically outperform NED/SED, but
by how much depends on code. For codes without known automorphism groups (like
FT8), SED and NED close the gap. No specific dB numbers were extractable from
search summaries (proxy-blocked); from the paper abstract, all methods improve
over standalone BP for short codes.

**Applicability to pancetta**:
- **SED**: ~20 LOC change to `ldpc.rs` — parameterize the layered-BP layer
  traversal order. Generate K permutations of the layer indices at compile time
  (or at `LdpcDecoder::new`) and run them in parallel via rayon.
- **NED**: ~25 LOC change — for each failed-BP candidate, add K Gaussian noise
  samples ε_k ~ N(0, σ²=0.1) to the LLR vector and re-run existing BP.
  σ is a single tunable parameter.
- Both are composable with SCED (hb-262) and APWBP (hb-264).
- The comparative study helps CHOOSE among ensemble methods for the FT8 code
  without running all of them: if MBBP/AED are impractical (unknown automorphism
  group), and SCED (hb-262 / aSCED, arXiv:2604.06889) is already being probed,
  then SED is the next cheapest incremental option.

**License**: Academic paper (Oct 2024, IEEE/arXiv dual-publication). No GPL;
implement from equations only.

### 3. hb-266 — Weighted Residual Layered BP (WR-LBP) (priority 0.25)

**Technique**: Within each layered-BP iteration, prioritize check-node updates
by the **residual magnitude** — the absolute change in a check-to-variable
message from its previous value. Messages with large residuals (most
out-of-date relative to the received LLR) are updated first. This is
"residual scheduling" applied inside the layered-BP framework (as opposed to
the flooding schedule). The paper couples residual scheduling with a learnable
per-message weight, giving "Weighted Residual Layered BP" (WR-LBP).

The key claim: WR-LBP converges in significantly **fewer iterations** than
plain layered BP for the same BER. For FT8 this means: given the same
`ldpc_iterations` budget, WR-LBP decodes more candidates per time budget
(processing more sync candidates) and converges better at the margin (candidates
that plain BP barely fails may converge under WR-LBP's prioritized schedule).

**Source**: arXiv:2410.13131, "Study of Weighted Residual Layered Belief
Propagation for Decoding of LDPC Codes" (H. Touati & R. C. de Lamare,
October 2024, IEEE ICCIT 2024; also ieeexplore.ieee.org/document/10639097/).

**Measured evidence**: The paper focuses on **convergence speed** (fewer
iterations to reach the same BER floor), not on SNR floor improvement. On
medium-to-long codes, WR-LBP reaches the target BER in ~40-60% fewer
iterations than plain layered BP. For short codes like FT8 LDPC(174,91),
the SNR floor improvement is less clear — pancetta's OSD already handles
non-converging candidates, so faster convergence translates to either
more candidates per slot or earlier OSD trigger.

**Applicability to pancetta**:
- **Attach point**: `pancetta-ft8/src/ldpc.rs`, the inner layered-BP scheduling
  loop. Replace the fixed layer-traversal order with a priority queue ordered
  by |Δm_{i→j}| (change in check-node-to-variable message). The priority queue
  updates each iteration.
- **Cost**: a binary heap per candidate decode (~O(E log E) overhead per iteration
  vs O(E) current). On a 174-bit code with ~750 edges this is negligible.
- **SNR floor uncertainty**: the paper tests medium codes. For short codes,
  residual-scheduling may not improve the floor since OSD already handles the
  non-convergence cases. Run kill-switch first.
- **Independent of SCED/APWBP/SED/NED**: WR-LBP is a scheduling improvement,
  not an ensemble method. It can be combined with any ensemble.

**License**: Academic paper (Oct 2024, IEEE). No GPL; implement from published
priority-queue scheduling description.

## Noted but not bank-worthy

### WSJT-X Improved v3.1.0 MTD (multithreaded decoder)

Released 2026-05-22, already covered in the June 22 scan. **No new releases
after June 22.** The MTD architecture uses time-staged decoding (STD @41ms +
final MTD @49ms, "2-stage"; or STD @41ms + STD @46ms + MTD @50ms, "3-stage")
that is equivalent to pancetta's existing rayon-parallel candidate processing
plus the a8 early-decode pass (hb-091, GRADUATED). The "intelligently combined"
language refers to different time-offsets feeding the union, not a new algorithm.
No new bank entry; WSJT-X Improved remains at v3.1.0.

### DECODIUM 4.0 "Shannon" EMA multi-period averaging

DECODIUM 4.0 "Shannon" (new release since June scan) ships "FT2 Multi-Period
Averaging" — EMA-weighted accumulation of complex spectra across 2–4 consecutive
FT2 slots (3.75s each) for a claimed +4 dB sensitivity gain. The FT2 decoder
runs 5 independent passes per slot, with one pass using MMSE channel estimation
and another using the EMA cross-period accumulation.

**Why not bank-worthy**: pancetta already ships **coherent MRC cross-cycle
integration** (hb-075, GRADUATED) for FT8's 15-second slots, which uses complex-
domain amplitude-weighted averaging — a provably stronger technique than EMA
(coherent combining is optimal for complex Gaussian channels; EMA is a scalar
approximation). The DECODIUM approach is FT2-specific (shorter periods, repeated
call patterns). No new entry.

### Spiking Neural BP Decoder for Short-Block LDPC (arXiv:2410.11543, IEEE ComL 2025)

SNN approximation of check-node update equations. Claimed advantage: energy
efficiency (event-based). Performance: "outperforms sum-product at **high** SNR."
FT8 operation is entirely in the **low-SNR** regime (the threshold region). SNNs
at high SNR are irrelevant to pancetta; energy efficiency on a ham-station CPU
is not a constraint. No bank entry.

### AR-CID: Adaptive Reliability-Driven Conditional Innovation Decoding (arXiv:2601.06732, Jan 2026)

Message quality checking + message-passing refinement in a residual-BP framework.
Results reported for parity-check matrix size (2048, 1024) — **medium-to-long
codes** — with fast convergence (7 iterations). FT8 LDPC(174,91) is a short code
where convergence behavior differs fundamentally. The gain mechanism (fast
convergence at moderate SNR) is already addressed by pancetta's 300-iteration
layered BP and OSD. No bank entry; tested only on long codes.

### Iterative Bounded Distance Decoding for GLDPC (arXiv:2507.12073, July 2026)

Generalized LDPC codes with small left degrees — a different code family from
FT8's standard LDPC (no generalized parity checks). Not applicable. No entry.
