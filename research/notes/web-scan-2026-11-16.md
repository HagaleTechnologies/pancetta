## Ranked candidates

### Rank 1 — jasiek/ft8-nn: open-source neural soft-demod for FT8/LDPC(174,91) (hb-279 draft)

**Technique:** GitHub repository `jasiek/ft8-nn` (Jan Mojžíš / jasiek). Last commit
2026-11-10, 67 commits. The decoder keeps FT8's standard LDPC(174,91) + CRC-14 pipeline
but replaces the hand-built max-log LLR computation (`par_compute_soft_llrs_db` in
pancetta's terms) with a small learned model `SoftDemod` that uses a convolution +
transformer architecture to map 79 symbol spectra (8 tone magnitudes per symbol) → 174
LLRs. The resulting LLRs feed straight into standard BP + CRC.

The idea: the max-log rule uses only the winning tone's magnitude, discarding the
remaining 7 tones' magnitudes which carry soft information about the channel state. A
neural model can learn to weight these tones jointly, capturing inter-tone correlations
that signal presence of interference, multipath, or noise floor shaping.

**Measured evidence (from README / bench output, Nov 10 2026):**

| Condition | jasiek/ft8-nn | jt9 (WSJT-X) | JTDX defaults | Method |
|---|---|---|---|---|
| AWGN, 50% threshold | −22.49 dB | −21.31 dB | (not given) | Synthetic AWGN, 10 signals/slot |
| AWGN gain over jt9 | **+1.18 dB** | — | — | Direct comparison |
| Fading (various) | +0.72–0.97 dB | — | — | Synthetic fading set |
| Real air, 4 unseen-receiver runs | +24% more decodes | jt9 baseline | +14.7% | on-air recordings |
| False decodes, 10K noise-only slots | **0** | n/a | n/a | Noise-only test |
| CPU per slot | ~2.8 s (1 core M4) | — | — | Apple M4 host |

These are author-reported figures from a single test machine (Apple M4 Pro, macOS 26,
arm64). The on-air runs are described as "unseen receivers" (independent data not used in
training). No third-party independent replication found.

**Primary source:**
- Repository: https://github.com/jasiek/ft8-nn (last updated 2026-11-10)
- Results file: bench/results (from README, specific URL not retrieved; repo is public)

**Applicability to pancetta:**
- FT8/LDPC(174,91) is the exact code in use. The ONNX model's declared input shape is
  **(B, 79, 48)** — 48 features per symbol, not 8 tone magnitudes (STATUS.md). The feature
  extraction upstream of LLR generation is part of the model's interface contract and cannot
  be reproduced by simply replacing `par_compute_soft_llrs_db`. A clean-room integration
  must implement the 48-feature extractor from the architecture description (not from source)
  before wiring into the LDPC chain. The resulting 174 LLRs still feed the existing SP-BP +
  OSD chain unchanged.
- **Architecture is tractable:** convolution + transformer on 79 symbols is a small model
  (~50–200K parameters estimated from README's training spec: "4 h on M-series MPS").
  The inference is per-candidate (each sync candidate gets its own LLR set), not
  per-slot: at pancetta's typical 50–200 candidates per pass this is 50–200 small-model
  forward passes per slot. At ~2.8 s / slot on M4 this is fast enough for 15 s slots but
  leaves limited headroom for other decode work. CPU-only inference will be slower.
- **Relationship to hb-095:** hb-095 ("Neural soft-demod replacement for max-log LLR",
  priority 0.25, wild) already specifies this technique with arXiv:2502.16371 (8-FSK dense
  NN) as the only supporting evidence. jasiek/ft8-nn is the first open-source, benchmarked
  implementation on FT8/LDPC(174,91) specifically, with real measured gains. This upgrades
  hb-095 from "speculative" to "has prior art, has numbers, has architecture". Priority
  should increase from 0.25 to ≥ 0.50.
- **Relationship to hb-187 (Wav2Vec2 adapter):** Both replace the front-end LLR
  computation with learned embeddings. hb-187 uses a frozen 95M-param pretrained SSL
  encoder; jasiek/ft8-nn trains from scratch on FT8 data, which removes the domain
  mismatch but requires FT8-specific training data. The two differ in scale, training
  regime, and interpretability. jasiek/ft8-nn is a lower-risk, more direct probe.
- **LDPC interaction:** the trained LLR distribution will differ from max-log's; existing
  LDPC knobs (parity_gate, llr_variance_target, etc.) may need re-sweep. This is the
  same risk noted in hb-095. The +1.18 dB result absorbs any such interaction (if the
  jasiek LDPC knobs are untuned, the tuned result could be larger).
- **License:** No LICENSE file found in the repository (all rights reserved by default).
  This requires the **clean-room spec firewall**: read the architecture description and
  train from pancetta's own synth corpus; do not copy model weights or training code.
  The training spec (input format, architecture type, loss function) can be described
  in a spec document by the reader, with the implementer working from spec only.
- **Training data:** jasiek/ft8-nn trains on synthetic AWGN-corrupted FT8 slots from a
  message set (ft8nn/data/messages.json). pancetta-research's synth generator can produce
  an equivalent corpus. No external proprietary data needed.

### Rank 2 — arXiv:2611.06874: Generalized Belief Propagation Network (GBPNet), cs.AI catch

**Technique:** arXiv:2611.06874, "Learning to Decode Linear Codes with Generalized Belief
Propagation Network" by Samira Malek (cs.AI, submitted ~2026-11-04). Extends the belief
propagation network (BPNet, Nachmani et al. 2016) by replacing each decoding iteration's
single variable sublayer with K ≥ 1 cascaded variable sublayers. For LDPC codes the
authors use L=3 sublayers; polar codes L=2; MacKay (96,48) L=5. Two training strategies:
progressive training (train K=1 first, add layers) and high-SNR training.

**Measured evidence (from search snippets only; full paper not fetched — arxiv.org DNS
blocked in this environment):**
- Claimed: lower BER than conventional BP and "evaluated state-of-the-art neural decoders"
  on BCH, polar, LDPC, and MacKay codes.
- Max 5 total decoding iterations.
- No specific dB numbers confirmed from available snippets.

**Primary source:**
- arXiv:2611.06874 abstract: https://arxiv.org/abs/2611.06874 (arxiv.org DNS-blocked; use
  Semantic Scholar or ui.adsabs.harvard.edu to access)

**Applicability to pancetta:**
- LDPC(174,91) is in scope (paper tests LDPC codes). No specific test on this code found
  in snippets; MacKay(96,48) is the longest tested code.
- 5-iteration cap is a potential limit: pancetta uses up to 100 iterations (hb-053). At
  5 iterations GBPNet may underperform pancetta's existing BP baseline at deep search;
  the gains would materialize only in the per-candidate pass-1 budget regime.
- Relationship to hb-195 (GNN over LDPC factor graph): hb-195 replaces message-passing
  with a GNN; GBPNet replaces variable nodes with K-layer MLPs. The approaches are
  compatible in spirit; GBPNet is a lighter-weight variant. hb-195 is already in bank.
- Training required; architecture is simpler than weighted-BP-ensemble (hb-276).

**Not bank-worthy at this time** without confirmed dB figures on LDPC(174,91) or a code
of similar length. Noted as a cross-category catch (cs.AI, not cs.IT — previously
uncovered by scans targeting cs.IT/eess.SP). Flag for follow-up when arxiv.org becomes
accessible: read §IV results on LDPC codes for specific gain vs standard BP.
