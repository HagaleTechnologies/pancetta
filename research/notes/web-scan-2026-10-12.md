## Ranked candidates

### Rank 1 — Squared metric (`imetric=2`) + pass gating (WSJT-X 3.2.0-rc1)

**Technique:** A variant demodulation metric in which the raw symbol power is
*squared* before being combined into the LLR estimate (`imetric=2` in
WSJT-X's `ft8b.f90`). "Pass gating" means specific decode passes (rather
than all passes) select this squared metric variant; other passes continue
with the linear-power metric. The combination is a form of per-pass metric
diversity.

**Primary source:** mfsk-core issue #447
(github.com/jl1nie/mfsk-core/issues/447), opened and closed Sep 24–26, 2026.
The issue is a WSJT-X 3.2.0-rc1 porting plan that includes component-level
ablation measurements on a real `jt9 -8 -d3` corpus. The ablation reverts
one change per build and measures the per-component sensitivity delta vs
WSJT-X 2.7:

| Component reverted | ΔdB vs 2.7 |
|--------------------|-----------|
| AP llrc pass (nsym=3) | +0.36 |
| Squared metric + pass gating | +0.33 |
| ndeep OSD cap removal | +0.14 |
| Fifth metric, nsync 7/8, MAXCAND | 0.00 |
| mlag 13 | −0.12 |
| **Total measured (all combined)** | **+0.33 to +0.84** |

The squared metric + pass gating accounts for +0.33 dB, tied with AP llrc
as the largest single contributors. The total sensitivity gain vs WSJT-X 2.7
was 0.33–0.84 dB on FT8; FT4 was unchanged.

**Relationship to hb-271 and hb-241:** hb-271 (WSJT-X 3.2.0-rc1
standard-decoder changes, Oct 5 scan) covered items sourced from issue
#435: AP pass doubling, apmag 1.01→1.1, ndepth OSD ungate, mlag 10→13,
nsync thresholds 6/7/8, SNR floor −25.0 dB. The **squared metric
(`imetric=2`) + pass gating was not in any of those items** — it first
appears in issue #447. However, `research/ideas_backlog.md:764-772`
already defines **hb-241** ("Per-pass parameter variation + skip-on-zero")
covering exactly this mechanism: WSJT-X's amplitude-vs-power imetric split
(pass 1 = amplitude/imetric=1, passes 2-3 = power/imetric=2), with the
schedule confirmed in `research/specs/spec-wsjtr-per-pass-variation.md`.
The issue #447 ablation data (+0.33 dB) is new quantitative evidence for
hb-241, not a new unmapped mechanism. **This candidate should update
hb-241's evidence and priority rather than create a separate entry.**

**Additional issue #447 findings (hb-271 status updates):**

  unless there is a specific corpus reason (e.g., late-arriving signals).
  The Oct 5 scan listed it as item 4 without measured cost; it now has one.
- "Fifth metric" (likely `imetric=4`), updated `nsync` thresholds 7/8,
  and `MAXCAND` were reverted as a **bundle** (one ablation row, 0.00 dB).
  Individual contributions within the bundle are unmeasured. These are not
  worth porting together unless they address a specific false-positive concern;
  any individual item would need its own arm to confirm a zero contribution.
- `/R` and `TU;` post-CRC filter (`.contest()` in the mfsk-core port): not
  in the ablation table, so its contribution is unmeasured. May address the
  contest-message FP problem; check against hb-072 (CQ whitelist, GRADUATED).

**Applicability to pancetta:**
- **LLR pipeline caution:** `pancetta-ft8/src/decoder.rs:9646-9699`
  (`compute_soft_llrs_db`) operates on values already in dB-domain and
  computes LLRs as max-vs-max differences of dB values, not `power /
  sum_power` ratios. Squaring power in the linear domain is equivalent to
  doubling the dB value; after `normalize_llrs`, that scalar factor cancels.
  The `power / sum_power → power² / sum_power²` framing from the upstream
  Fortran does not map directly to pancetta's pipeline. The implementation
  path for `imetric=2` must be investigated against the actual dB-domain
  demapper — the spec in `research/specs/spec-wsjtr-per-pass-variation.md`
  covers the per-pass schedule but not the dB-domain translation.
- **Pass direction (per WSJT-X spec):** Pass 1 uses amplitude metrics
  (`imetric=1`); passes 2-3 use power metrics (`imetric=2`). In pancetta's
  0-indexed pass counter this is: `pass_idx == 0` → amplitude; `pass_idx
  >= 1` → power variant. The schedule is specified in
  `research/specs/spec-wsjtr-per-pass-variation.md:106-113`.
- **Multi-pass eval requirement:** `Ft8Config::default().max_decode_passes`
  is 1 (`decoder.rs:1901`), and the eval harness uses the production default.
  A single-pass probe always runs pass_idx=0 (amplitude) and never exercises
  the pass_idx>=1 power metric. Probes must explicitly set `--max-passes 3`
  (matching upstream) to test this mechanism at all.
- **Early-stop caveat:** `decode_window` breaks when `pass_unique.is_empty()`
  (`decoder.rs:4685-4690`): if pass 0 (amplitude) finds nothing, the loop
  exits before pass 1 runs — exactly the weak windows where the power metric
  might rescue decodes. Per `spec-wsjtx-mainline-ft8-decode.md:230-232`,
  upstream uses **previous-pass gates**: pass 2 is skipped if pass 1 produced
  0 decodes; pass 3 is skipped if pass 2 added 0 new decodes (not a
  cumulative check — pass 3 can be skipped even when passes 0+1 found
  signals if pass 2 adds nothing). The probe must disable the
  pass-0→pass-1 early-stop so pass 1 (the first power pass) always executes;
  the remaining previous-pass gates (pass-1→pass-2, pass-2→pass-3) must be
  retained to reproduce upstream behaviour. If all early-stops are disabled,
  this becomes a separate exploratory arm, not a reproduction of the cited
  mechanism.
- **LLR whitening interaction — not applicable:** `llr_whitening_enabled`
  defaults to `false` (`decoder.rs:1151-1160`); the corrected whitening was
  re-shelved after Task W1.4 measured -56 TPs on hard-200. The interaction
  concern does not apply to the default pipeline. If testing alongside
  whitening (opt-in A/B), treat as a separate arm.
- Measurement target: hard-200 recall delta vs. baseline (with `--max-passes
  3`); noise_1000 false-positive gate; elapsed-time gate.

**License note:** WSJT-X 3.2.0-rc1 is GPLv3; mfsk-core is GPL-3.0 (every

## Noted but not bank-worthy

### Semantic OSD (arXiv:2605.02296, May 2026)

"Semantic Ordered Statistics Decoding" (Yue, Vucetic, Li; U. Sydney, May 2026)
proposes augmenting OSD with a byte-level language-model prior to prioritize
test error patterns for byte-streamed source codes (natural-language text).
The LM drives both basis selection and codeword candidate scoring.

Not bank-worthy for FT8: FT8's 77-bit message space is a fixed, enumerable
protocol structure (callsign × grid × report), not a continuous byte stream.
Structured priors are already injected via AP (hb-048/hb-271) at the LDPC
level, which covers the FT8 equivalent. The OSD-TEP diversity the LM
provides would add little beyond what AP injection already does for a
39-word vocabulary of message templates. License: unknown; irrelevance
makes it moot.

### ft8ts (github.com/e04/ft8ts, active 2026)

Pure TypeScript port of WSJT-X v3.0.1 FT8/FT4 decoder, browser-native.
Runs at depth 1–3 (values above 3 treated as depth 3). Implements a7
(cross-slot decode reuse, equivalent to WSJT-X's a7 mode) and synchronized
multipass subtraction across parallel sub-band threads (threads meet after
every pass to subtract each other's signals). These techniques align with
mfsk-core 0.12.0's FT8/FT4 cross-stream subtractive cancellation (yanked
2026-10-03, superseded by 0.13.x which retains it); both derive from the
WSJT-X 3.x lineage. mfsk-core 0.13.0/0.13.1 (released Oct 4–5, current
stable) further port FT8 syncmin/passes/OSD/nfqso-first from v3.2.0-rc1.
No isolated sensitivity benchmarks found vs. a comparable baseline.
Not bank-worthy: a7 and multipass subtraction are tracked in existing
hypotheses; the TypeScript target is inapplicable to Pancetta's Rust pipeline.
